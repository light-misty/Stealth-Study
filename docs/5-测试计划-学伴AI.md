## 1. 测试范围与总体策略

### 1.1 测试对象与范围

测试对象为基于 OpenWorker 二次开发的学伴 AI 桌面应用（仓库内部代号 HIU-WorkSpace / coworker），覆盖：

- P0 公共基础功能：B-01 ~ B-07、B-11、B-13、B-14
- P1/P2 功能：B-08、B-09、B-10、B-12
- 三备考台内容层：C1-01~05、C2-01~04、C3-01~04
- 非功能需求：性能、安全、隐私与本地优先、离线可用性
- 明确不在测试范围：语音功能（B-04 为负向验证）、教师端/管理端、外部连接器、MCP、编码代理、团队多 agent

### 1.2 三层测试分工

| 层级 | 框架与命令 | 职责 | 对应验收层 |
|------|------------|------|------------|
| 单元测试（Python） | pytest，`pytest tests -q`，约 135+ 个既有测试文件，共享 fixtures 见 `tests/conftest.py`（`isolated_state_dir`、`fake_slack`） | 工具层与逻辑层：write_file 参数校验/越权拒绝/覆盖保护、grep 检索返回格式、memories 表 CRUD 与卡片类型字段、persona manifest 解析（ships/group 前缀）、Schedule cron 解析、providers registry 工厂 | B-05、B-07、B-11、B-14 的核心逻辑与全部负向路径 |
| 单元/组件测试（前端） | Vitest，`npm test`（`surfaces/gui/`） | 组件渲染与交互状态：Composer 语音按钮条件渲染、PersonasTab 三人设渲染、i18n 默认 zh 与持久化、Markdown 流式渲染、资料库列表/筛选组件 | B-02、B-03、B-04、B-06、B-11 的 UI 逻辑 |
| E2E 测试 | Playwright，`npm run e2e`（`surfaces/gui/e2e/`，共享 fixtures 见 `e2e/fixtures.ts`） | 真实用户路径：Onboarding→BYOK 配置→对话→保存→资料库→检索→闪卡复习全闭环；语音入口全局不可见 | 全部 10 条验收标准的最终权威验证 |

分工原则：

- **负向与安全类断言（越权路径、覆盖保护、静默写盘禁止）必须在 pytest 单元层覆盖**，E2E 只做代表性正路径，避免 E2E 层堆积安全用例。
- **UI 可见性断言（语音按钮不存在、人设可选）在 Vitest 组件层精确断言，E2E 层做全局兜底扫描**（如整页 DOM 内检索语音相关选择器为空）。
- **核心闭环（讲解→保存→检索→复习）必须有一条贯穿的 E2E 冒烟用例**，作为 I1 准出条件。

## 6. 测试环境与数据准备

### 6.1 测试环境

| 环境 | 说明 |
|------|------|
| 单元/组件测试环境 | 本地开发机；pytest（`pytest tests -q`）与 Vitest（`npm test`，`surfaces/gui/`）；全部使用 mock，无真实 Key 与真实网络 |
| E2E 环境 | Playwright（`npm run e2e`，`surfaces/gui/e2e/`），复用 `e2e/fixtures.ts`；模型调用全部指向 mock 提供商 |
| 跨平台冒烟环境（I4） | Windows / macOS / Linux 各一台，安装打包产物执行冒烟集 |

### 6.2 BYOK 模拟（mock 提供商）

- pytest 层：沿用既有 fake 提供商 fixture 思路（参考 `fake_slack` 的注入模式），注册一个返回固定流式分片的 mock 提供商工厂，支持注入延迟、分片间隔、错误（5xx/断流）三种场景开关。
- E2E 层：拦截/本地 stub 模型 endpoint，返回预置 Markdown 讲解文本（含标题/列表/代码块/表格，供 TC-B03-02 与 TC-B05 断言）。
- Key 统一使用形如 `sk-test-mock-0000` 的假 Key，禁止在测试库中提交任何真实 Key。

### 6.3 样例资料文件

| 样例 | 用途 |
|------|------|
| `sample-真题-阅读.md`（含中文与英文段落、多级标题） | B-13 导入、B-14 中文/英文检索 |
| `sample-讲义-数学.md`（含公式文本、代码块、表格） | B-13、B-14 格式兼容性 |
| `sample-单词表.txt`（50 个词条） | B-14 检索、C1-02 单词卡生成 |
| 空 Markdown 文件、超大 Markdown（约 5MB） | B-05/TC-B05-09、B-13/TC-B13-05 边界 |
| 预置落盘集：`<workspace>/.xueban/notes/` 下 3 篇笔记、2 道错题、1 份词表 | B-06 浏览/检索/复习、B-07 检索衔接 |

### 6.4 人设 fixture

- 三份最小 manifest fixture：`xueban-cet` / `xueban-kaoyan` / `xueban-cert`，frontmatter 含 `ships: true`、`group: general`、`tools`（声明 write_file）、skills 字段，正文为各台讲解风格的最小 system_prompt。
- 一份负向 fixture：`xueban-evil-group`（`group: other`）用于验证非 VALID_GROUPS 分组被拒绝（回归枚举校验）。
- fixture 人设仅供测试注入，不进入 release 分发。

### 6.5 隔离与幂等

- 所有涉及 workspace 与 state 的 pytest 用例必须基于 `isolated_state_dir` 类隔离 fixture，禁止写入真实用户目录。
- E2E 每个用例前重置 workspace（临时目录），保证用例独立可重复执行。
