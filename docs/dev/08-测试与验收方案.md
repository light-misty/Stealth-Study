## 3. V0.0 三个 spike 的量化验收标准（对应 T01-T04）

### 3.1 SPIKE-1 批改 JSON 输出（T01）

| 指标 | 量化门槛 | 不达标的处置 |
|---|---|---|
| L0 成功率（`degrade_level=0` 占比） | 本地 7B/8B **≥60%** | 低于 60% → `GRADING_START_LEVEL=1`（06 §8-3 一行常量），V0.1 批改默认从 L1 起步 |
| L0+L1 合计成功率 | **≥90%** | 低于 → 批改端点前置"模型能力提示"（EmptyModelGuide 文案），CERT 主观题批改降 P1（决策门预案） |

| 批改一致性 | 推荐模型、`degrade_level=0` 样本：同一作文两次批改**档位一致率**按 PRD §5 CET-09 验收口径执行（样本 10 篇 × 2 次） | 低于口径 → rubric prompt 增加"先逐段摘证据再定档"的两步指令重测 |

### 3.2 SPIKE-2 中文 PDF 按页召回（T02）

| 指标 | 量化门槛 | 不达标的处置 |
|---|---|---|

## 4. profile_id 守卫固化用例（对应 T06，`tests/campus/test_profile_guard.py`）

| 用例 | 场景 | 请求 | 断言 |
|---|---|---|---|
| P-1 缺失 | 不带 profile_id 调任意需档案端点（如 `GET /v1/campus/profiles/xxx/plans`） | query/body 无 profile_id | 422 或 `PROFILE_NOT_FOUND`（与 03 文档错误码表一致），**不得**返回空列表静默通过 |
| P-2 伪造 | `profile_id="nonexistent-uuid"` | 同上 | `PROFILE_NOT_FOUND`，无任何库读副作用（store 查询计数 = 1 次存在性检查） |
| P-3 跨档案 | 档案 A 存在；用档案 B 的 profile_id 读档案 A 的 attempt/doc/plan 子资源 | `GET /v1/campus/grading/{attempt_id}`，attempt 属档案 A | `FORBIDDEN_PROFILE`（403 语义）；service 层 `WHERE profile_id=?` 双保险生效（越界查询行数 = 0） |
| P-4（附加）只读档案 | 档案已归档后调用写端点 | `POST /v1/campus/attempts` | `PROFILE_READ_ONLY` |

三条用例参数化覆盖全部需要档案的端点组（A/B/C/D/E/F/I 组各抽 ≥1 端点），不是只测一个。

## 5. 结构化解析与一致性测试（对应 T07/T21）

1. **rubric 一致性（CI 硬门禁）**：解析 7 个 SKILL.md 的评分标准章节 ↔ `rubrics.py` 对应常量，`strip()` 后**全等比对**（05 §4.2）。任一侧改动未同步 → CI 红。fixture 兼容 markdown 表格的行内空白差异（去行尾空白后比对）。
2. **解析器单测（17 用例，06 §7-1）**：`_extract_json`（```json 围栏/嵌套大括号/字符串内大括号/截断/首尾噪音/空响应 8 例）；L1 填空正则（缺行/全角冒号/错误行超限截断/空槽位 6 例）；L2 聚合（档位矛盾反推 `band_reconciled`/得分点越界/轮次超预算 3 例）。纯函数，不 mock 模型。
3. **schema 白名单校验**：`band` ∈ {0,2,5,8,11,14}（作文）越界拒收；三维 0-5 且档位区间一致性；`errors[].type` ∈ `ERROR_TYPES_CET`；非法即按降级处理并记 `schema_violation`（不是抛异常）。
4. **降级链路集成（mock 回放）**：用 T01 真实样本构造"先坏后好"序列（第 1 轮 JSON 坏 → L1 成功），断言 `degrade_level=1` 落 `attempt` 表、`_degrade_trace` 记录中间 reason、响应带降级提示字段。
5. **真题回归**：CET 官方样卷 2 篇（有标准分档）作 golden case：推荐模型输出档位与官方档位一致（样本固化在 `tests/campus/fixtures/`）。

## 6. i18n 双语一致与 key 完整性（对应 T15/T22）

1. **既有门禁不放宽**：`locales.test.ts:31-38`（zh/en key 集合严格相等）campus 命名空间同样受检；`i18n.test.ts` 插值占位符检查继续生效。
2. **campus.* key 完整性双向扫描**（新增 `src/campus/__tests__/i18nCoverage.test.ts`）：① 组件源码内 `t("campus.xxx")` 引用集合 ⊆ zh.json 定义集合（无漏 key 运行时裸露）；② zh.json 的 `campus.*` 定义 ⊆ 引用集合 ∪ 显式白名单（无死 key）。白名单仅限 P1 预留 key 并注释用途。
3. **复数/插值规则**：含 `{count}` 的 key 双语均有 `_one/_other` 或等价处理；测试遍历 key 元数据表断言。
4. **硬编码扫描**：`components/campus/**` 与 `campus/**` 源文件 grep 不得出现裸中文/裸英文 UI 字符串（正则扫描测试），免责声明"AI 生成，仅供参考"必须是 i18n key（PRD §7.6）。
