### 1.3 通用约定

| 约定 | 规则 |
|---|---|
| 主键 | `id TEXT PRIMARY KEY`，值 = 应用层 `uuid.uuid4().hex`（32 位小写）。SQLite 无原生 UUID 类型，与既有 `personas.json` 风格一致 |
| 时间戳 | `TEXT`，ISO 8601 UTC（`2026-09-08T12:00:00Z`）。日期字段（`exam_date` 等）用 `YYYY-MM-DD`。**统一 UTC 存储、前端按 locale 渲染**（PRD §7.5） |
| JSON 列 | `TEXT` 存 JSON 字符串，读取时 `json.loads`。用于选项、评分结果、配置数组等半结构化数据 |
| 外键 | **不启用 SQLite 数据库级外键约束**（不设 `PRAGMA foreign_keys=ON`），引用完整性由应用层（`campus/service.py` / `store.py`）保证。理由：① 与既有内核一致（`memory/sqlite_store.py` 的 `memories` 表无外键约束）；② 级联清理（删资料、删档案）需要在应用层做文件系统联动，DB 级 CASCADE 反而碍事。本文表格中的 `FK→` 标注为**逻辑外键**，是应用层必须维护的关系 |
| 软删除 | 仅 `exam_profile` 有归档态（`status=archived/finished`）；其余表**硬删除**，但删除档案（profile）时必须按 §7.3 的级联顺序清理 |
| 枚举 | 全部用 TEXT 存小写字符串，取值见各表"取值"列；`campus/models.py` 中定义同名 Python Enum，写入前校验 |
| 计数列 | `knowledge_point.question_count / mistake_count` 是冗余计数（列表页免 join），由 `service.py` 在写入 `question_bank_item` / `mistake_book` 时同步增减，不靠触发器 |

## 2. 连接管理与两库隔离

### 2.1 CampusStore 连接模式（照抄 + 一处增强）

严格照抄 `ss/memory/sqlite_store.py:13-43` 的模式（`check_same_thread=False` + `threading.RLock` + 单条长连接 + 构造时建表），仅做一处增强：追加 `PRAGMA journal_mode=WAL`（FastAPI 多线程 handler + 前端轮询下，WAL 让读写不互斥）。

```python
# ss/campus/store.py （骨架，完整实现见 07 文档 T03）
import sqlite3, threading, uuid
from pathlib import Path
from ..secrets import state_dir

class CampusStore:
    def __init__(self, path: str | Path | None = None) -> None:
        self.path = str(path or (state_dir() / "campus.db"))
        Path(self.path).expanduser().parent.mkdir(parents=True, exist_ok=True)
        self._lock = threading.RLock()
        self._conn = sqlite3.connect(self.path, check_same_thread=False)
        self._conn.row_factory = sqlite3.Row
        self._conn.execute("PRAGMA journal_mode=WAL")   # 与 sqlite_store.py 的唯一差异
        self.migrate()                                   # 见 §3，含版本检查

    @staticmethod
    def new_id() -> str:
        return uuid.uuid4().hex

    def close(self) -> None:
        with self._lock:
            self._conn.close()
```

规则：

1. **单例**：`CampusStore` 实例由 `build_campus_router(manager)` 构造并持有（见 §3.4 启动时机），进程内共享，不重复开连接。
2. **所有读写持锁**：方法体内 `with self._lock:` 包裹（照抄 `sqlite_store.py` 的做法）。
3. **不修改 `ss/memory/sqlite_store.py`**，不 import 它（避免类型耦合），只照抄模式。

### 2.2 与 ss.db 的隔离三原则（对应 01 文档 §4.3）

1. 两个库、两条连接、两个 store 类；campus 对 `coworker.db` **零直连**（不 `sqlite3.connect` 该路径）。
2. 语义记忆（"用户听力篇章弱"等）写入 `coworker.db.memories` **只通过既有 memory 工具链**；`memories` 表结构不修改。
3. 删除 `campus.db` 与 `campus/` 目录后主程序不受影响（PRD §13-B6 已核验：无任何既有代码引用该路径）。

## 3. schema_meta 版本迁移机制（INF-01）

### 3.1 表结构

```sql
CREATE TABLE IF NOT EXISTS schema_meta (
    key        TEXT PRIMARY KEY,     -- 固定 "schema_version"
    version    INTEGER NOT NULL,
    applied_at TEXT NOT NULL          -- ISO 8601 UTC
);
```

### 3.2 版本号与迁移组织

- `CURRENT_SCHEMA_VERSION = 2`（v1 = V0.1 全量建表；v2 = `exam_profile.archived_at`，见 §4.3）。
- 迁移表 `_MIGRATIONS: dict[int, Callable[[sqlite3.Connection], None]]`：键 = 目标版本号，值 = 该版本的 DDL/数据迁移函数。**每个版本一个函数，禁止修改已发布的迁移函数**（只允许追加新版本）。
- 版本比较规则：
  - `stored < CURRENT`：按版本顺序逐个执行迁移；
  - `stored == CURRENT`：无操作；
  - `stored > CURRENT`（用户回滚了应用版本）：**拒绝初始化**，抛 `SchemaVersionError`（明确报错，不静默降级，PRD §7.6 原则），提示"学习数据库由更新版本创建"。

### 3.3 迁移执行器

```python
def migrate(self) -> int:
    with self._lock:
        self._conn.execute(SCHEMA_META_DDL)
        row = self._conn.execute(
            "SELECT version FROM schema_meta WHERE key='schema_version'").fetchone()
        current = int(row["version"]) if row else 0
        if current > CURRENT_SCHEMA_VERSION:
            raise SchemaVersionError(f"campus.db schema v{current} > app v{CURRENT_SCHEMA_VERSION}")
        for v in range(current + 1, CURRENT_SCHEMA_VERSION + 1):
            self._backup_before(v)                      # 复制 campus.db → campus.db.bak-v<from>
            try:
                self._conn.execute("BEGIN")
                _MIGRATIONS[v](self._conn)              # 该版本全部 DDL/DML
                self._conn.execute(
                    "INSERT INTO schema_meta(key,version,applied_at) VALUES('schema_version',?,?) "
                    "ON CONFLICT(key) DO UPDATE SET version=excluded.version, applied_at=excluded.applied_at",
                    (v, _utcnow()))
                self._conn.execute("COMMIT")
            except Exception:
                self._conn.execute("ROLLBACK")
                raise                                    # 中止启动，不静默
        return CURRENT_SCHEMA_VERSION

    def _backup_before(self, v: int) -> None:
        shutil.copy2(self.path, f"{self.path}.bak-v{v - 1}")
```

### 3.4 启动检查时机（不新增既有文件改动）

迁移在 **`build_campus_router(manager)` 构造 `CampusService` 时执行**（路由挂载即初始化）。时机链：

```
server/app.py create_app()
  → app.include_router(build_campus_router(manager))     # 唯一侵入点（01 文档 #9）
      → CampusStore()          # migrate() 在此执行，失败即抛异常、启动中止
      → CampusService(store, config)
      → 注册路由（闭包持有 service）
```

不需要也不允许改 `server/manager.py`（其 `:220` 附近的 store 初始化序列保持原样）。迁移失败的表现是**应用启动失败 + 明确错误日志**，符合"不静默失败"原则；`campus.db.bak-v*` 备份保证可手工恢复。

### 3.5 V0.2 迁移示例（写进规范，防止届时乱改）

```python
def _v2_add_column(conn: sqlite3.Connection) -> None:
    # 先查列是否存在（PRAGMA table_info），再 ALTER —— 允许对旧库幂等重放
    cols = {r["name"] for r in conn.execute("PRAGMA table_info(attempt)")}
    if "degrade_level" not in cols:
        conn.execute("ALTER TABLE attempt ADD COLUMN degrade_level INTEGER")
```

## 5. `doc_chunk` 切片粒度与索引设计（ADR-08 的数据侧）

### 5.1 切片粒度

| 规则 | 取值 | 理由 |
|---|---|---|
| 基本单位 | **一页一片**（`chunk_type='page'`，`page_no` = pypdf 页序） | 页码引用（KY-09 验收 2）天然成立；pypdf 逐页提取无需额外分页逻辑 |
| 超长页 | 单页字符数 > **6,000** 时二次切分（`chunk_type='split'`，同页多行，`char_start/char_end` 标记区间），切片上限 **8,000 字符** | 控制组卷预算（`token_est`）；按 128K 窗口，6-8 片 × 4K token ≈ 30K，留足对话空间 |
| 章节归属 | `section_title` 从 PDF 书签（pypdf outline）提取；无书签时由 LLM 对**目录页**一次性抽取章节→起始页映射，回填到各片 | 目录路由（检索 L1）的候选清单来源 |
| 不做摘要 | `content` 存原文 | 引用保真；摘要由回答时的模型按需生成 |

规模预估：200 页文档 ≈ 200-240 片 ≈ 60-80 万字符 ≈ 1-2MB/文档。整库千片量级，**所有 SQLite 方案（含 LIKE 扫描）都在毫秒级**，这是不引入 embedding 的量化底气。

### 5.2 检索索引：三级策略（配合 `library.retrieve()`）

| 级别 | 机制 | 适用 | 依赖 |
|---|---|---|---|
| **L1 目录路由（主力）** | `SELECT DISTINCT section_title, MIN(page_no) FROM doc_chunk WHERE doc_id=? GROUP BY section_title` 取目录清单 → 喂模型选 top N 章节 → `WHERE doc_id=? AND section_title IN (...)` 取原文 | 章节式提问（"讲讲分部积分"） | 仅普通索引；7B 模型做选择任务可靠 |
| **L2a FTS trigram** | 可选虚表 `CREATE VIRTUAL TABLE doc_chunk_fts USING fts5(content, content='doc_chunk', content_rowid='rowid', tokenize='trigram')`，trigram 对中文按 3 字滑窗，无需分词 | 关键词型提问（"先验分布出现在哪"） | CPython 3.11+ Windows 官方构建的 SQLite ≥ 3.34，支持 trigram；**构建前运行时探测**（`SELECT * FROM pragma_compile_options()` 不含 `ENABLE_FTS5` 则跳过创建） |
| **L2b LIKE 退化** | `WHERE doc_id=? AND content LIKE '%关键词%'` + Python 侧按命中密度打分 | FTS5 不可用时的兜底；千片量级全扫 < 50ms | 无 |

**决策**：V0.1 默认启用 L1 + L2b（零探测成本）；L2a 的 trigram 方案作为 V0.0 中文召回 spike 的对比项（`08-测试与验收方案.md` §4.2），spike 结论决定是否启用。**明确不引入 embedding / 向量库**（PRD v1.1 A 类⑧）。

### 5.3 同步维护

- `doc_chunk` 与 FTS 虚表用外部内容表（`content='doc_chunk'`）模式，写入时由 `store.py` 同一事务内维护（`INSERT INTO doc_chunk_fts(rowid, content) SELECT rowid, content FROM doc_chunk WHERE doc_id=?`）。
- 删除资料：`DELETE FROM doc_chunk WHERE doc_id=?` → `INSERT INTO doc_chunk_fts(doc_chunk_fts) VALUES('rebuild')` → 删 `source_doc` 行 → 删 `campus/library/<profile_id>/<doc_id>/` 目录（顺序固定，失败即中止并保留记录一致）。

## 7. 数据生命周期

### 7.1 一键清除（PRD §7.3）

删除 `campus.db`、`campus.db.bak-v*`、`campus/` 目录。实现：关闭连接 → 删文件 → 重建空库（`migrate()` 重跑）。**不清 `coworker.db`**。

### 7.2 档案归档与只读

`exam_profile.status` 流转：`active ↔ archived`、`active → finished`（PRD §6.4）。`finished` 档案：`service.py` 拒绝一切写请求（返回明确错误），数据保留可导出——应用层守门，不靠触发器。

### 7.3 删除档案的级联顺序（应用层执行，单事务 + 目录清理）

```
1. review_queue   WHERE profile_id=?
2. mistake_book   WHERE profile_id=?
3. attempt        WHERE profile_id=?
4. question_bank_item / vocab_item / mock_exam / assessment / weekly_report / cert_deadline / mastery
5. plan_task → study_plan
6. doc_chunk（+FTS rebuild）→ source_doc → 删 campus/library/<profile_id>/ 目录
7. school_profile → knowledge_point
8. exam_profile
```
顺序原则：先删叶子引用，最后删根；文件目录删除放在 DB 事务成功之后（DB 是权威，文件可重导）。

### 7.4 导出 / 导入（INF-02/03）

导出格式：单 JSON 文档（19 张表各一数组，`schema_meta.version` 一并写入）。导入：校验 `schema_version ≤ CURRENT`，在空库事务内重放 + 迁移到当前版本。导出文件落 `campus/exports/`。
