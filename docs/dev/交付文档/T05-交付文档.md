### 3.2 真实模型抽查（T5.7）

以真实密钥对静态清单里声明的两个 DeepSeek 最小可用模型各发一次极短请求（提示"只回复两个字：收到"），实测：

| 模型 | 结果 | 用量 |
|---|---|---|
| `deepseek:deepseek-v4-pro` | 通过（返回正文，`finish_reason` 非 `length`） | 输入 ~90 tokens / 输出 ~30 tokens |
| `deepseek:deepseek-v4-flash` | 通过 | 同上量级 |

**抽查发现（已修复）**：两个模型都是**带推理段**的模型——首次以 `max_tokens=8` 请求时，预算被推理段占满，`text` 为空且 `finish_reason='length'`（响应里推理字段可见"我们需要回答用户。用户说…"）。用例因此把预算定为 128 并显式断言 `finish_reason != 'length'`。这条对 T07 有直接意义：批改的 JSON 输出预算必须为推理段留量，否则会得到"空正文 + 截断"而不是解析失败，降级链根本不会被触发。

## 6. 移交 T06 的接口要点

1. `build_campus_router(manager)` 内构造 `CampusStore()`（迁移即在此时执行，失败即启动失败），再构造 `CampusService(store, CampusConfig)`（02 §3.4）。
2. `get_profile` 依赖校验存在性与档案状态后注入 `ExamProfile`；子资源越界一律 `FORBIDDEN_PROFILE`，实现上直接用 `store.get_scoped()`，越界会得到 `None`。
3. 档案状态守门用 `models.ProfileStatus`（`active/archived/finished`）；`finished` 档案拒绝一切写请求。
4. 库版本倒挂的异常类型是 `store.SchemaVersionError`，错误文案已含两侧版本号，可直接透出为启动期明确报错。
5. 三台配置取 `tracks.spec_for(track)`；新台只需往 `TRACKS` 加一项，`service`/`routes` 不应出现按台分支。
