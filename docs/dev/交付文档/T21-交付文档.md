### 3.2 全量回归

**方法**：以基线提交 `55868b2` 建纯基线工作树（`git worktree add --detach ../Stealth-Study-t21-base 55868b2`），两棵树分别跑 `pytest tests -q --tb=line`，取 `FAILED`/`ERROR` 行去消息、排序后 diff，要求**集合逐条相同**。

| 项 | 纯基线树（`55868b2`） | 分支树（`fb9d435`） |
|---|---|---|
| 汇总行 | `100 failed, 2909 passed, 29 skipped, 3 warnings, 9 errors in 265.52s` | `100 failed, 2930 passed, 27 skipped, 3 warnings, 9 errors in 267.91s` |
| 失败集合大小 | 109 条（100 `FAILED` + 9 `ERROR`） | 109 条 |
| 差集 | — | **仅分支有 0 条 / 仅基线有 0 条**，`diff` 判定 **IDENTICAL** |

结论与说明：

1. **失败集合逐条相同**（`comm -13` 与 `comm -23` 均为空）。这是本阶段唯一有效的回归判据——只比"失败条数"会漏掉真实回归（见下）。
2. `+21 passed` 的构成：新增 `tests/campus/test_persona_bundles.py` 的 19 例，加上 `tests/campus/test_mount.py` 的两条侵入预算守卫在功能分支上不再 `pytest.skip`（`HEAD != main`）而多出的 2 条通过。
3. `−2 skipped` 正是上一条那两条守卫在基线树上的跳过——**预期差异，不是噪声**（该机制与基线 +2 skipped 的经验一致）。
4. **109 条既存失败全部是本机环境所致，与 T21 无关**：108 条源于沙箱拦截子进程创建（`FileNotFoundError [WinError 2]`，另有一条来自 subprocess reader 线程的 `UnicodeDecodeError` 属同一根因），1 条是 `tests/test_secrets.py::test_secrets_file_is_restricted` 在 Windows 下的 `TypeError`（文件权限检查依赖非 Windows 语义）。判断依据不是"看起来像"，而是这 109 条在两棵树上逐条相同。

### 3.5 环境限制与未执行项（诚实说明）

1. **真实模型链路未跑**：08 §5.5 的"真题回归（CET 官方样卷 2 篇作 golden case）"与"人设会话真实模型下的技能触发效果"**本阶段未执行**——本机无可用云厂商 API Key，且该口径本就不进 CI。因此"7 个技能在真实对话中会被模型正确触发"这一条**没有直接证据**，只有机制层证据（目录注入 + `load_skill` 可取全文 + allowlist 收口）。
2. **端到端引擎构造受阻**：`SessionManager.get_engine()` 会走 `LocalExecutor` → `subprocess.Popen`，本机沙箱拦截子进程创建（`FileNotFoundError [WinError 2]`），故**未能**在引擎级验证 `load_skill` 工具被注册进人设会话的 registry；退化为对 `skill_tools(loader, allowed)` 与 `persona_skill_scope()` / `effective_skill_names()` 的直接验证（§3.3(d)）。该限制是环境性的，与 T21 改动无关：纯基线树上 `tests/test_persona_connections.py::test_declared_connector_allowlist_gates_session_tools` 同样失败（§3.2 对照已确认）。
3. **GUI 侧未做浏览器实测**：验收 ① 的"选择器可见"以后端端点 `GET /v1/personas` 的响应为准——该端点（`ss/server/app.py:260`）就是侧栏选择器的取数入口（`api.ts:1138` `getPersonas()`，消费方 `Sidebar.tsx:277`、`App.tsx:408`），前端无第二套硬编码名单；**未**启动 Tauri/dev server 点开选择器目视确认。
4. **5 个技能包没有一致性门禁**：8 §5.1 写"解析 7 个 SKILL.md 的评分标准章节 ↔ rubrics.py 对应常量"，实际只有 3 个 SKILL.md 承载 rubric 章节（`cet-essay-grading`、`cet-translation-grading`、`mistake-attribution`）；其余 4 个（`cet-listening-drill`、`mock-exam-proctor`、`kaoyan-weekly-review`、`cert-knowledge-tree`）在 `rubrics.py` 里没有对应常量，因此**未加逐字门禁**（见 §5 差异 2/3）。
