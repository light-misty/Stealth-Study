自动化端点。两点口径先行说明（诚实登记，见 §5-1）：

* 07 原文写「追加 F 组自动化端点（03 §4.9）」——03 §4.9 实为 I 组（自动化模板/人设/导出），
  F 组（CET）已由 T10 交付。本阶段按 03 §4.9 交付 **I2/I3**；I1（人设）归 T21、I4-I6（导出
  导入）归 T14。
* **D4-D6（复习队列端点）由本阶段承接**：T10 交付文档 §5-8 明确登记「D4-D6 由 T13 承接复
  习队列」，`service.py` 中 F7 处的移交注释与 01 文档给 `review_scheduler.py` 的三个函数契
  约（`next_interval` / `apply_result` / `due_items`）同指此处。D1-D3/D7（错题本与 AI 归因）
  不在本阶段范围（见 §6 移交）。

实际交付 **5 个端点 + 2 个新模块**：

| 组 | 端点/模块 | 需求 | 要点 |
|---|---|---|---|

| D4 | `POST /review/items` | CERT-03/CET-02 | 素材须存在且属于该档案（`ITEM_NOT_FOUND`/`FORBIDDEN_PROFILE`）；pending 幂等不重置进度；`done` 历史行存在时重开新一轮；次日 00:00Z 到期，与 F7 的 `_enqueue_vocab_review` 同口径 |
| D5 | `GET /review/due` | CET-05/G-17 | `pending` 且 `due_at <= as_of`（缺省取服务器当前时刻），按到期时间升序；payload 内联错题/词卡/知识点内容；悬空引用跳过不炸 |
| D6 | `POST /review/{rq_id}/result` | CET-05 | 答对沿 1/2/4/7/15 天阶梯推进 `streak_right`/`interval_days`，答错重置回 1 天并归零 streak；`correct` 用 `StrictBool` 拒绝 `"yes"`/`1` 一类隐式真值 |

| tpl_id | 标题 | kind | 计划 | 前置 |

## 2. 验收标准对照（07 §4 T13）

| # | 验收标准 | 结论 | 证据 |
|---|---|---|---|
| ① | 间隔函数单测（0-5 连对的间隔序列） | 通过 | `test_interval_ladder_matches_the_prd_table`：streak 0-5 → 1/1/2/4/7/15（0 为答错重置口径，与 PRD §6.3 表逐行一致）；封顶（6/7/20/100 次 → 15 天）与端到端版 `test_d6_full_ladder_across_five_correct_reviews`（HTTP 连对五次间隔依次 1/2/4/7/15） |

开发方式为 TDD：三个测试文件均先写、先确认 RED（模块缺失 404/ModuleNotFoundError），
再实现确认 GREEN。开发中发现并修复的问题：

1. **D6 `correct` 的隐式真值**（测试先行捕获）：Pydantic v2 默认把 `"yes"`/`1` 归一为
   `True`，`{"correct": "yes"}` 会 200 且按答对处理——批改结果被静默改写。改用
   `StrictBool`，非 JSON 布尔一律 422。
2. **D5 排序用例与部分唯一索引冲突**：同一 `(profile_id, item_type, item_id)` 只允许一条
   pending（02 §4.15），排序用例改用两条真实词卡种子，顺带验证了索引约束生效。
3. **错误码门同步**：新增 `TEMPLATE_NOT_FOUND` 后 `test_routes_errors.py` 的契约等式断言
   变红，按该门的既有分组（03 §4 用到但 §6 未列）登记。

## 5. 与文档的差异登记

1. **07 §4 T13 的「F 组自动化端点」为笔误口径**：03 §4.9 是 I 组；本阶段交付 I2/I3，
   并按 T10 交付文档 §5-8 的移交承接 D4-D6（07 原文未点名 D 组归属）。D1-D3/D7、B 组、
   I1、I4-I6 仍无归属，见 §6。
2. **新增错误码 `TEMPLATE_NOT_FOUND`（404）**：03 §6 无「模板不存在」的行，但 I3 的
   `tpl_id` 是路径参数，未知 id 必须可拒绝。已按 `test_routes_errors.py` 的既有分组登记，
   建议随 T14/T23 补进 03 §6 正表。
3. **D5 的 `as_of` 只接受完整 ISO 时间戳**（`YYYY-MM-DDTHH:MM:SSZ`，422 拒绝其它形状）：
   due_at 比较是字符串字典序，纯日期会导致"当日到期"语义歧义，故收紧而非猜测。
4. **D4 幂等口径**：pending 已存在时**原样返回**（不重置进度、不改到期时刻）——02 §4.15
   的"重复加入走 UPSERT"按最保守解释落地；`done` 行存在时新建 pending（部分唯一索引只
   约束 pending，允许重开新一轮）。
5. **节点提醒模板的数据源是 `exam_date`**（PRD G-18 的"节点提醒 once"），不是
   `cert_deadline` 表——H9（CERT-13 的 D-30/D-7/D-1 经 `cert_deadline` 建 once 任务）属
   T12，两者并存不冲突。已过期的 offset 跳过不建（`compute_next_run` 对过去时刻返回
   NULL，建了也永不触发）。`fire_at` 取本地 09:00，依赖既有 `compute_next_run` 的本地
   墙钟 + DST 语义。
6. **模板幂等靠 `origin_session_id` 标记**（`campus-tpl:<tpl>:<profile>[:<offset>]`）：
   `ScheduledTask` 无标签字段，标题可被用户改名，故不取标题；标记扫描一次 `TaskStore.list`
   即判定，被手动删除的模板任务可重装。创建路径完全复用 `manager.create_automation`
   （工作区供给、校验一致），campus 不绕过它直接写 `TaskStore`。
7. **`review_intensity`（间隔强度偏好）未参与算法**：PRD §6.3 明确"V0.1 固定，不做算法
   调优"，阶梯表为唯一口径；设置项仅在 A6/A7 中透传展示（T09 既有行为），留待 V0.2。
8. **D6 对 `done`/`dropped` 行为未定义**：当前实现允许对任意状态行回写结果，回写后状态
   落回 `pending`（等价"复活"）。现状无任何写入方产生 `done`/`dropped`（F7 掌握度路径尚
   不清理队列行），该状态只能经 D1-D3/CERT 流程或手工数据出现——建议 D1-D3 交付时定义
   "标记已掌握 → 队列行置 `done`"并决定 D6 是否拒绝非 pending 行。
9. **模板 instructions 为内置中文文案常量**：描述目标、数据位置与"不编造"约束，不承诺
   具体工具链（自动化运行时如何调 campus API 由 agent 能力决定）；文案口径可由主理人后续
   调整，不影响调度与幂等语义。
10. **F6/F7 与 D5 的重叠是有意的**：F6 的 `review_items` 是 CET 词卡视图（只含 vocab），
    D5 是全类型复习队列视图；两者共用同一 `review_queue`，口径一致（含次日 00:00Z 的
    入队时刻）。

## 6. 移交 T14/T21-T23 的接口要点

   `_enqueue_vocab_review`、本阶段 D4。三者幂等口径一致（pending 唯一），后续写入口
