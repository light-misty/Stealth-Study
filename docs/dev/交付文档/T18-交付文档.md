## 2. 验收标准对照

### 2.1 07 §5 T18 的三条验收标准

| # | 验收标准 | 实现与实测 | 判定 |
|---|---|---|---|
| ① | 四轨任务数=周数渲染正确 | "每轨每周 1 个周级任务"是后端 F5 的结构不变量（T11 交付），前端职责是渲染不失真：`PlanBoard` 按 ISO 周一日期分组（`mondayOf`，UTC 算术），组间按周升序、组内按日期+id 排序；用例覆盖两周分组、跨月同周合并（2026-09-30 与 2026-10-01 归入 2026-09-28 周）；环形按 `progress.by_track` 实际键渲染（不硬编码四轨名单，兼容 KY-02 异构三轨档案），每轨显示 done/total 与 0-1 rate 环形 | 通过 |
| ② | 重排后已完成任务不移位 | 日期保留由后端 G3 保证（done/doing 原日期）；前端闭环：`PlanPanel` 组合层让 `PlanEditor` 与 `PlanBoard` 共享同一份 `usePlanTasks` 数据，重排成功后触发 reload，集成用例断言第二次加载的新数组中 todo 日期已移动（09-08→09-15）而 done 任务行仍显示原日期（09-07） | 通过 |
| ③ | KY-03 列表确为只读 | `PlanBoard` 全组件无 button/input/select/textarea/[draggable] 元素，无状态改写/拖拽回调；用例以 DOM 查询断言 `container.querySelector("button, input, select, textarea, [draggable='true']")` 为 null（含 todo/doing/done 混合数据渲染时） | 通过 |

### 3.2 异常输入与边界场景

- 后端 422 `EXAM_DATE_REQUIRED`：PlanEditor 渲染 i18n 译文（en "Set the exam date first"）且不触发刷新回调；
- 空计划/空周报/空资料/空进度各有专门空态文案；
- 跨月同周、跨轨同周、同日多任务排序边界；
- 请求在途时全部提交入口双锁（生成/重排/批改/问答），不产生重复请求；
- 加载失败可重试（retryable 判定走 `campusErrorInfo`），失败不污染已有数据（UPSERT 回滚语义在钩子层）。

## 4. 与文档的差异登记

1. **新增组合组件 `PlanPanel`（07 清单外第 6 个文件）**：`PlanEditor`（操作）与 `PlanBoard`（展示）必须共享同一份任务/进度数据，重排后看板才能同步刷新（验收②的 UI 闭环）；`CampusStationView` 的扁平面板表无法表达"两面板一状态源"，故新增组合层，`TRACK_PANELS` 只挂 `PlanPanel` 一行。07 清单中的两个组件均在其内，无功能遗漏。
2. **`MajorQAView` 替换 kaoyan 台的共享 `QAChatPanel`**：T16 原配置在 kaoyan 槽位挂共享问答；T18 按 07（KY-9）替换为专属视图（资料选择器 + 引用点击）。`campus-qa-input`/`campus-qa-send`/`campus-citation` 等 testid 与 QAChatPanel 保持一致，e2e 兼容；QAChatPanel 本体保留未删（其他台/未来可复用）。
3. **`useLibraryQA.ask` 增加 `docOverride` 可选参数**（既有 hooks 文件的最小改动）：原 hook 的 docId 在创建时闭包绑定，MajorQAView 的资料选择器需要每次提问运行时切文档；旧调用（QAChatPanel）不传该参，行为不变。
4. **`layering.test.ts` 扫描 glob 由 `../*.tsx` 扩为 `../**/*.tsx`**：原 glob 只扫 campus 顶层，T18 的 `kaoyan/` 子目录组件会逃过分层门禁；扩展后 glob 同样会覆盖未来 T17/T19 的子目录组件（当前两分支未合并，合并后自动纳入）。
5. **热力图渲染口径**：G4 的 `heatmap` 只含有完成记录的日期（后端设计，"热力图数据与实际完成记录一致"），非固定 84 天网格；前端按返回数组渲染，每日期一格、`data-count` 标注，强度三档（≥4/≥2/其他）。若主理人期望固定周网格视图，属 V0.2 增强。
6. **验收①的实现分工**：任务数=周数由 T11 后端代码保证（非模型发挥）；前端以"周分组渲染不失真"为验收口径，并在交付文档中如实区分，未在前端重复实现计数校验。
7. **locales 重复键修复**：`campus.kaoyan.tutor.kind` 曾同时以字符串（label）与对象（题型名）出现——JSON 解析后字符串被覆盖，label 实际不生效；已将 label 改名为 `kind_label` 并去除重复键。
8. **i18n 插值规避复数机制**：新增计数文案（`generated`/`rescheduled`/`group_summary` 等）统一用 `{{total}}/{{moved}}/{{kept}}/{{done}}` 命名，避开 i18next 对 `{{count}}` 的 `_one/_other` 复数展开；既有 `progress.streak` key 本就按复数对定义，直接复用。

## 5. 遗留与建议

1. **T20 接入**：`App.tsx` surface 三元链追加 `kaoyan` 即可让本阶段面板全部可达；e2e 建议顺延到 T20 一并补齐。
2. **与并行分支的合并顺序**：T17（cet）/T19（cert）分支同样会在 `locales/zh.json`/`en.json` 追加各自 key 子树，并可能各自扩展 `TRACK_PANELS` 配置表；建议合并时以 key 子树为单位解冲突（本分支改动集中在 `campus.kaoyan.*`），配置表冲突按"各台追加各自行"原则手工合并。
3. **`PlanBoard` 环形配色**目前统一用主题 `accent`；如需四轨异色（政治/英语/数学/专业课各一色），建议在 V0.2 与主题 token 一起规划。
4. **`SubjectTutorChat` 的 rubric 入口**未暴露（C1 的 `rubricId`/`customRubric` 可选参数未提供 UI）；当前后端按考研默认量表批改，若需要自定义量表入口属新需求。
