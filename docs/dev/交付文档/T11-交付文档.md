## 1. 功能范围与任务清单

### 1.1 范围界定

**做**（07 §4 T11 的交付范围，全部在 `ss/campus/service.py` + `routes.py` 追加，07 涉及文件清单之外的既有源码改动为 **0 行**）：

1. **F5 计划生成**（`POST /plans/generate`，KY-01/02 与 CET-03 按 TrackSpec 分台共用）：
   - 结构由代码保证（T11 验收①不依赖模型发挥）：从今天到考试日，**每轨每周 1 个周级任务**（周级任务数 = 周数）、**每天 1 个日级任务**按轨轮转、四轨全部有任务（无空轨）；阶段按 06 §2 PlanStage 四段比例（基础 40%/强化 30%/真题 20%/冲刺 10%，不足四周时按周序取段），周级任务优先级随阶段（冲刺/真题 1、强化 2、基础 3）；
   - 档案 `subjects` 收窄并排序科目轨（`subjects ∩ TrackSpec.subject_skeleton`），实现 KY-02 异构验收（"不考数学 + 两门专业课"三轨 vs 默认四轨，结构明显不同）；骨架为空的档案回落单一 `overall` 轨；
   - 模型只贡献每周主题文案（`_weekly_themes`，单次调用、temperature 0、90s 超时、`response_format` 语义对齐 T07）：输出不可用**降级**为确定性标题（03 §4.4 F5 未登记 `MODEL_OUTPUT_INVALID`）；未配模型 `MODEL_NOT_CONFIGURED`、调用失败/超时 `MODEL_TIMEOUT`；缺/无效考试日期 `EXAM_DATE_REQUIRED`；
   - 落库：`study_plan` 一行（track=overall、start/end 日期、source=ai_generated）+ `plan_task` 批量插入（单事务）。
2. **G2 任务写回**（`PATCH /tasks/{task_id}`，KY-03 看板拖卡 / ADR-11）：状态流转严格按 PRD §6.4 状态机（`TASK_TRANSITIONS`：todo→doing/skipped、doing→review/skipped、review→done/review 自环、done/skipped 终态），非法流转 `ILLEGAL_TRANSITION`（409）；进入 done 落 `completed_at`，重复 done 不刷新；改期/改优先级不是状态流转、任何状态合法（优先级 1-3 与生成器刻度一致）；`board_card_id` 保持不写。
3. **G3 一键重排**（`POST /plans/{plan_id}/reschedule`，KY-04/KY-13）：done/doing 原样保留（T11 验收②），todo 任务按原相对顺序（日期/优先级/创建序）**等距摊铺**到"今天 → 新考试日"；完成率落后计划预期进度 ≥15% 的轨其 todo 任务优先级提为 1（落后轨加权，KY-13 口径：预期进度 = 计划 start→end 时间轴上今天的位置，计划无有效跨度时以整体完成率为基线）；提供 `new_exam_date` 时同步写回 `exam_profile.exam_date` 与 `study_plan.end_date`，两端永不分歧。
4. **G4 进度总览**（`GET /progress`，KY-11）：`by_track` 按 `plan_task.subject` 聚合 done/total/rate；`streak_days` 从今天（今天未打卡则从昨天）向回数连续打卡天；`heatmap` 只认 `completed_at`（G2 写回的真实时间戳），不凭 `status=done` 倒推日期——"热力图数据与实际任务完成记录一致"（KY-11 验收 3）。
5. **G5/G6 周报**（`POST /weekly-reports/generate`、`GET /weekly-reports`，KY-12）：按含今天的 ISO 周聚合，**确定性数据聚合、无模型调用**（03 §4.7 给 G5 只登记 `NO_TASK_DATA`；AI 周报内容经 T13 自动化模板进入）；content_md 为 05 §4.7 固定五段（总览/各轨明细/新增错题 TOP/落后预警/下周建议）；未完成原因归类（拖了/卡住了/超量，另设"计划内"与"本周之前遗留"）；错题 TOP 取本周新增且出现 ≥2 次的知识点（无 point_id 按 subject 兜底，≤5 条）；落后预警复用 KY-13 的 ≥15% 口径并引导一键重排；下周建议 ≤5 条、每条带预计用时；一周一报（`UQ idx_wr_week`）同周重复生成 UPSERT。
6. **G7/G8/G9 院校档案**（KY-14）：G7 读（未保存返回 `id=None` 空壳，03 未给 G7 登记错误码，读不 404）；G8 部分字段 UPSERT（字段形状对齐 02 §4.4：`degree_type` 枚举、`recommend_ratio` 0-1、`past_scores` 须含 `{year, line}`，非法体 422）；G9 简章抽取走与 F5 相同的 `_complete_json` 链路，只保留合法字段并按"抽到字段数/8"计 `confidence`，输出坏掉降级为空 prefill 而非报错。
7. **profile 横切**：全部端点沿用 T06 `ProfileGuard`（读 `get_profile`、写 `get_writable_profile`），`finished` 档案拒绝一切写入；plan/task 资源经 `get_scoped` 档案域校验。
8. 测试 6 个文件 105 例 + 契约清单扩展：`test_routes_plans.py`（14）、`test_routes_task_patch.py`（40）、`test_routes_progress.py`（9）、`test_routes_weekly_reports.py`（16）、`test_routes_school_profile.py`（17）、`test_routes_kaoyan_flow.py`（9）；`test_campus_flow.py` 的挂载契约清单登记 T11 全部 9 个新端点（`T11_ENDPOINTS`）。

**不做**（按 07 §4 T11 的任务边界与并行任务划分）：

- 不做 CET 台其余端点（T10：F1-F4/F6-F14 定级、词汇、模考状态机）——F5 虽为共用端点，但 CET 侧仅以 TrackSpec 驱动的通用分台路径覆盖（`test_f5_serves_the_cet_station_from_the_same_code_path`），不新增任何 CET 专属端点；
- 不做复习调度与自动化模板（T13，AI 周报模板在 I3 落地）；
- 不做导出导入（T14）；KY-05/06/07/08 的作答与批改复用 T07 C1/T09 E5（无新端点）；KY-09/10 复用 T08 B6/B7（无新端点）；
- 不改 `teams/` 看板（ADR-11：`board_card_id` 保留不写，字段为 V0.2 只读同步预留）。

## 2. 验收标准对照

### 2.1 07 §4 T11 的三条验收标准

| # | 验收标准 | 实测 | 判定 |
|---|---|---|---|
| ① | 计划生成：四轨周级+日级、每周任务数=周数、无空轨 | `test_routes_plans.py`：默认四轨 102 天（15 周）计划 → 每轨周级任务恰 15 个且全部落在 7 天网格上、日级任务共 102 个（逐日轮转）、每轨非空；`task_count = 周数×轨数 + 天数`；全部 todo 且 `board_card_id` 为 NULL；模型主题进入周级标题、模型输出坏掉时结构不变（`test_f5_survives_unusable_model_output`）；两年期（100 周）与 6 天（1 周）短周期同规则成立；CET 台走同一代码路径产出四题型轨（无 `if track == ...` 分支，01 §3.2） | 通过 |

## 5. 与文档的差异登记

## 6. 移交要点（T13/T14/T17-T20/T23）

1. **F5**：端点已按 TrackSpec 分台，CET 前端（T17）可直接以 `POST /plans/generate` 生成备考计划；KY 前端（T18）表单只需保证 `exam_date/subjects/daily_minutes` 已写入档案（A2/A4），再调 F5 即可，无需传计划参数。`task_count/first_date` 直接驱动生成结果摘要卡。
2. **G2**：看板四列（待学/在学/待复习/已掌握）映射 `todo/doing/review/done`；拖卡只发 `{"status": "..."}`，409 `ILLEGAL_TRANSITION` 应提示不可回退的列间移动；`skipped` 为隐藏终态（可提供"跳过"动作）。`skipped/review` 列语义见 §5 差异 1。
3. **G3**：一键重排返回 `{rescheduled, preserved_done}`，前端以"已重排 N 项、保留 M 项已完成"反馈；修改考试日期场景建议先调 G3（携带新日期）一次完成，无需再调 A4。
4. **G4**：`heatmap` 为有完成记录的日期升序数组（稀疏，无零填充），前端按日历渲染缺省为 0；`streak_days` 已内置"今天未打卡从昨天起算"的宽容逻辑。
5. **G5/G6**：`content_md` 即导出 markdown 全文（五段）；`suggestion` 为纯文本行列表（`1. ...`），前端可按行渲染为建议卡片；同周重复生成幂等（UPSERT），cron 模板（T13/I3）可直接复用本端点语义而不产生重复行。
6. **G7/G8/G9**：初始态以 `id is None` 判断；G9 返回的 `prefill` 仅含抽取成功的字段，前端应逐字段高亮预填并让用户确认后经 G8 落库（confidence < 3/8 时建议引导手动填写，KY-14 验收 1 的"≥3 字段"按此判断）。
7. **错误映射**：本阶段全部错误码取自 03 §6 既有表，端点层经 `_call`/`_async_call` 统一翻译，无需新增映射。
8. **测试基建**：`FakeManager`（get_settings + provider.complete 回放）与 `_utc_today`/`_utcnow_iso` 的 monkeypatch 模式可直接复用于 T13（自动化模板调 F5/G5）与 T23（E2E-4 KY 计划与周报）的用例搭建。
