## 4. 关键实现决策与文档差异登记

1. **鉴权头**：03 §1 / 04 §6.1 写 `X-StealthStudy-Token`，但真实后端 `ss/server/app.py:199` 校验的是 `x-ss-token`（T06 已按此实现并通过 `test_mount.py`），既有 `api.ts:29` 亦用 `X-SS-Token`。campus/api.ts 按真实后端落 `X-SS-Token`，以实现为准。
2. **A10 函数名**：04 §6.2 的 `setOfflineMode(on)` 与 03 §4.1 的 A10（`DELETE /v1/campus/privacy/data`，一键清除本地数据 `{cleared, freed_bytes}`）不一致。按 04 §9"后端契约细节以 03 文档为准"落 `clearPrivacyData()`。
3. **F7 词汇掌握度取值**：03 §4.6 写 `mastery: "known"|"fuzzy"|"unknown"`，但后端 `models.py` 的 `MasteryLevel` 与 02 §4.11 的合法值是 `unknown/fuzzy/mastered`，不存在 `"known"`。`setVocabMastery` 按 `MasteryLevel` 类型落（`"mastered"`），`api.test.ts` 固化该契约，防止 03 文档笔误渗入前端。
4. **端点/函数计数口径**：03 文档官方计数 72 = 端点表 72 行；其中 E4、H3 各含 PATCH+DELETE 两个 HTTP 操作，I5 为下载链接（04 §6.2 注明"直用 httpBase() 不封装"）。因此 api.ts 实际导出 **74 个函数**（73 个请求函数 + `exportDownloadUrl` URL 构造器），`CAMPUS_ENDPOINTS` 清单 74 个操作、72 个行号 id；脚本比对按行号 72/72 断言无缺无增。"72 个函数"按 07/08 原文口径理解为"72 行端点全覆盖"。
5. **error i18n key 命名**：03 §6 / `routes.py ERROR_SPECS` 的错误码为大写 snake，04 §7.2 要求 key 全小写，映射规则为 `code.toLowerCase()`（`campus.error.model_timeout` 等）。覆盖 `routes.py` 全部 **37** 个错误码——比 03 §6 表多出 T06 实现阶段新增的 `FORBIDDEN_PROFILE`、`ASSESSMENT_NOT_FOUND`、`ITEM_NOT_FOUND`、`NO_TASK_DATA`。
6. **JSON 列的 TS 形态**：02 §4 中 TEXT 存 JSON 的列（`subjects`、`options`、`answers`、`locked_stages`、`automation_ids`、`past_scores` 等）在 types.ts 中按 04 §6.3 约定声明为解码后的结构化类型（数组/对象/嵌套节点），对齐服务端 JSON 序列化语义；`attempt.grading_json` 按行契约保留原始 JSON 字符串类型（C2 响应），消费侧解析。
7. **复数 key 规则**：en 侧 `days_left_one/_other`、`streak_one/_other`，zh 侧仅 `_other`；同时满足 `locales.test.ts` 的 baseKeys 比对与 `i18n.test.ts` 的"en 非法 `_one` 键可缺席于 zh、其余键逐字相等"双规则。
8. **路由声明顺序提示（移交后端）**：C3 `/grading/history`、C4 `/grading/common-errors` 与 C2 `/grading/{attempt_id}` 同前缀，T09 实现 service 端点时须将字面路径声明在路径参数之前，避免 FastAPI 路由遮蔽。

1. **pytest 全量未在本机执行**：本机无 `.venv` 与后端依赖（仅有系统 Python 3.13.7）。本阶段 `git diff` 仅触及 `surfaces/gui/` 下 10 个文件（§1.4 清单），零 Python 改动，pytest 基线不受影响；CI 的 `pytest` job 按既有流程覆盖后端回归。
2. **死 key 双向扫描未在本阶段实现**：08 §6.2 的 `i18nCoverage.test.ts`（组件引用 ↔ 定义双向比对）依赖 T16-T19 组件落地后才有引用集合，归属 T22/T23；本阶段骨架 key 的 zh/en 对等性已由门禁覆盖。
3. **开发环境备注**：本机首次搭建 GUI 工具链——winget 安装 Node.js v24.19.0（LTS），`npm ci` 安装 350 包；本机 npm 安全机制要求对 esbuild 的 postinstall 显式 `npm approve-scripts`（仅本机行为，已还原 `package.json` 不入库）。推送期间本机 GitHub 加速代理（hosts 指向 127.0.0.1 的本地回环代理）出现间歇性中断，均已重试成功，未采用"只提交不推送"豁免。
4. **e2e 未涉及**：`surfaces/gui/e2e/` 仍为零 spec（08 §9 风险 1），campus e2e 归 T23。
