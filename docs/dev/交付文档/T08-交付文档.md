### 1.1 范围界定

**做**（07 §4 T08 的交付范围，全部 **L0 纯新增**，对既有源码改动为 **0 行**）：

1. `ss/campus/library.py`（915 行）：资料库与检索的完整库层——
   - **解析**：pypdf **逐页**提取（06 §8-1，不调 `pdf_support.extract_text()` 整本接口、`pdf_support.py` 零修改），`strict=False` + 逐页 try/except + 空文本合法，与 `pdf_support.py:117` 同款容错；
   - **切片**：一页一片（`chunk_type=page`）、单页超 2000 字符按 `\n\s*\n` 段落边界二切（`chunk_type=split`，每片 ≤2000、重叠 0、`char_start/char_end` 全文精确偏移）、单文档 3000 片上限（超出抛 `TooManyChunks` 中止导入）；
   - **章节归属**：**书签优先**（pypdf outline 扁平化 → 有效条目门槛 → 跨度计算含同页塌缩回退），无有效书签回退**文本行方案**（放宽标题正则容忍空白 + 编号式分支、同一标题 stem 出现 ≥3 页视为运行页眉剔除）；MD/TXT 按 `#{1,3}` 标题切伪页；
   - **判空分支**（06 §6.1 四情形，不静默）：`no_text_layer` / 部分页空占比 >80% 升级 / `pdf_broken`（损坏与带口令）/ `truncated_2m`（截断，已提取页正常入库）；
   - **三级检索**（06 §5.1）：L1 目录路由（标题占比 ≥50% 门控 + 06 §5.2 原文 prompt + 解析含剥行尾页码/最短标题门槛/最长匹配/去重 ≤3）、L2 关键词召回（`extract_terms` 对齐 T02 spike：拉丁词元 + 原文滑窗 2-gram 去停用字 + **IDF 加权** + 首次命中位置评分）、L3 全扫兜底（`doc_id=None` 时 `WHERE profile_id=?`）；
   - **FTS5 加速档**（02 §5.2 L2a）：显式 `enable_fts=True` 时才探测 `ENABLE_FTS5` 并建 trigram 虚表 + 维护触发器，探测/建表/运行时 MATCH 任何一步失败自动退回 LIKE，两态对上层透明；
   - **`answer_qa`**（06 §5.3，async + `asyncio.to_thread`）：检索 → 片段头部 `[资料名 p.X]`、单片截 2000、总量 ≤12000 → provider 生成 → `p.X` 反查 citations（无标记时兜底附全部用到的切片，06 §5.3-3 兜底必填）；
   - **库层 CRUD**：`import_pdf`（落盘 + 建行 + 同步解析）、`retry_parse`（B5：扫描件幂等拒绝 `DOC_SCAN_EMPTY` 不再烧解析）、`delete_doc`（B4 级联：删 chunk → 删行 → 删目录）；
   - **`LibraryError`**：领域错误携带 03 §6 错误码（`DOC_NOT_FOUND`/`DOC_NOT_READY`/`DOC_SCAN_EMPTY`/`MODEL_NOT_CONFIGURED`/`MODEL_TIMEOUT`/`MODEL_OUTPUT_INVALID`/`UNSUPPORTED_TYPE`/`PARSE_ERROR`），T09 端点据此映射 HTTP 错误体。

## 6. 移交 T09 的接口要点

1. **构造**：`CampusLibrary(store, lib_dir=None, provider=None, model_picker=None, *, enable_fts=False)`。`lib_dir` 缺省 `state_dir()/campus/library`；`model_picker` 缺省 `models.pick`（QA 与路由均走 `models.pick("explain", track_type)`，`config.resolve_task_model` 可作配置覆盖封装）；`enable_fts` 为 FTS 加速档显式开关（V0.1 默认 False，对上层透明）。
2. **B1**（`POST /library/import`）：端点层做大小/类型前置校验（`FILE_TOO_LARGE` ≤10MB、`UNSUPPORTED_TYPE`）后调用 `lib.import_pdf(profile_id, file_path)`——同步解析在请求线程内完成（06 §6.1 判定时机），返回的 SourceDoc 已是终态（ready/failed）；`LibraryError`（`UNSUPPORTED_TYPE`/`PARSE_ERROR`）直接 `raise_campus_error(exc.code, exc.message)`。
3. **B2/B3**：列表与轮询纯 store 查询（`store.list_rows("source_doc", profile_id=..., order_by="imported_at DESC")` / `guard.scoped_row("source_doc", doc_id, profile_id, missing_code="DOC_NOT_FOUND")`），不需要 library 参与。
4. **B4/B5**：`lib.delete_doc(profile_id, doc_id)`、`lib.retry_parse(profile_id, doc_id)`；`LibraryError.code ∈ {DOC_NOT_FOUND, DOC_SCAN_EMPTY}` 按码透传即可。
5. **B6**（`POST /qa`）：`await lib.answer_qa(profile_id, question, doc_id)`（async，内部 `asyncio.to_thread`，与 `GradingEngine.grade` 同构）；返回 `{answer, citations: [{doc_id, page_no, snippet}], used_retrieval: "toc_route"|"keyword", chunks_used}`，`citations` 在检索成功时必非空（KY-03 页码引用硬验收的前端数据源）。
6. **B7**（出题，T11 落地）：复用 `lib.retrieve(profile_id, query, doc_id=...)` 取片段后按 06 §5.3-4 组出题 prompt（L1 填空模板复用 `grading.py` 解析器）。
7. **错误映射**：`LibraryError` 的 `code` 均取自 03 §6 表，端点层统一 `except LibraryError as exc: raise_campus_error(exc.code, exc.message)`。
8. **profile 守卫**：library 层按 `store.get_scoped` 双保险（跨档案读返回 `DOC_NOT_FOUND` 语义由 `_require_ready_doc`/`retry_parse`/`delete_doc` 落实），端点层仍需 `Depends(guard.get_profile)` 做第一道 `PROFILE_REQUIRED/PROFILE_NOT_FOUND` 拦截（P-1/P-2 用例）。
