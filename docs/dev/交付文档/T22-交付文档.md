## 3. 测试与验证

### 3.1 验收标准 ①：zh/en base key 对称性

**方法：**

1. 以 JSON 解析读取 `zh.json` / `en.json`，取 `campus` 命名空间子树。
2. 递归展开为点分路径列表（叶子节点才被展开，对象节点继续递归）。
3. 后缀剥离（`_zero/_one/_two/_few/_many/_other` → base key），去重后比较 zh/en 的集合差。

**工具：** PowerShell `ConvertFrom-Json` + 自制 Flatten 函数（见 §5 环境说明）。

**结果：**

| 项 | zh.json | en.json |
|---|---|---|
| 叶子 key 数（含复数） | 1825（全文件）/ 304（campus） | 1865 / 304 |
| base key 数（去复数后缀） | 304 | 304 |
| zh ⊂ en 的缺位数 | 0 | — |
| en ⊂ zh 的缺位数 | — | 0 |

`missingInZh = []`，`missingInEn = []`。等价测试逻辑同 `locales.test.ts:31-38`，结果可直接推出 Vitest 测试流过。

**`locales.test.ts` 预期输出：** `locale completeness > en.json and zh.json declare the same key set`：PASS。

### 3.2 验收标准 ②：关键使用率扫描（缺位检测）

**方法：**

1. 静态扫描所有 `surfaces/gui/src/**/*.tsx`：`grep -rohP 't\("campus\.[a-zA-Z0-9_.]+"\)'` 提取静态 key。
2. 识别 4 处动态模板拼接（`t(\`campus.cert.deadline.node.\${option}\`)` / `t(\`campus.common.mastery.\${level}\`)` / `t(\`campus.cet.assessment.section_\${s}\`)` / `t(\`campus.cet.mock.stage_\${exam.current_stage}\`)` 等），由源码推断变量取值集合，一并加入使用集合。
3. 全集去重后为 `all_used_keys.txt`（220 条 base key）。
4. 与 locales 定义的 base key 集合作 `comm -23`（缺位） 与 `comm -13`（死 key）双向比对。

### 3.3 复数规则核对

根据 `locales.test.ts:22-28` 的 `baseKeys()` 语义，英文需要而中文不需要的 `_one` 复数形式被 base key 剥离合法化：

- 中文仅 `_other`：`campus.cet.errors.times_other`（出现 {{count}} 次）/ `campus.mistake.count_other`（共 {{count}} 条）/ `campus.mistake.wrong_count_other`（错 {{count}} 次）/ `campus.kaoyan.progress.streak_other`（连续学习 {{count}} 天）/ `campus.common.days_left_other`（还剩 {{count}} 天）。
- 英文对应 `_one` + `_other`：`campus.cet.errors.times_{one,other}` / `campus.mistake.count_{one,other}` 等，复数双语齐备。
- base key 剥离后 zh = en。

复数规则核对结论：双语严格对称（base key 集合差为 0），满足 04 §7.2 第 2 条规则。

### 3.4 `campus.ai_notice`（AI 免责声明）

`campus.common.ai_notice = "AI 生成，仅供参考"`（中）/ `"AI generated, for reference only"`（en），04 §7.1 要求的 AI 免责声明就位。
