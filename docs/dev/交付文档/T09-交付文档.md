### 3.2 开发中发现并修复的问题

1. **`tests/campus/test_mount.py` 的两条预算用例已失效（既有测试，随分支暴露）**：用例把
   "分支工作树 = `main` + 本次补丁"写成等式（`sorted(touched) == ["M\tss/campus/config.py",
   "M\tss/server/app.py"]`、`app.py` 的 numstat `== 40\t2`），而 G-06（`config.py` 的
   `login_enabled` + `app.py` 的 42 行 = 40/2，正是 `APP_PY_PATCH` 本身）**已经合入 `main`**：
   `git show --stat 63797d7` 显示该笔即 `app.py | 42 ++++`，`git diff --numstat main -- ss/server/app.py`
   为空。因此任何从当前 `main` 切出的分支上，`config.py`/`app.py` 相对 `main` 都无差异，等式断言必然红
   （T06/T20 时该用例在基线提交上走 `skip`，故未暴露）。**修复**：改写成真实不变量——改动文件
   ⊆ 已登记补丁 ∪ `ss/campus/`（本特性自有包）的子集断言；`app.py` 预算断言改为"无差异，或恰好等于
   已登记预算"。卡点强度不变：卡点外的任何改动仍然红。修复后该校验由 skip 变为真实执行（campus
   跳数 6→4），提交 `8c75439`。
2. **`store.insert()` 的自动补列范围再次被实测确认**：T06 §7-6 已记录 `source_doc.imported_at`
   不在自动补列名单内；本阶段构造级联测试数据时 `mistake_book.last_wrong_at` 同样报 NOT NULL 失败。
   两条均属既有约束（T05 的设计），非缺陷；已作为移交要点登记（§6-4）。
3. **得分点制题型的 L3 回落形态（引擎既有行为，需下游知情）**：`short_answer` 等评分点题型只有
   L0 一档（06 §3.5），L0 解析失败时引擎按 `raw_text` 回落为 `degrade_level=3, ok=True`，
   `grading_json` 中 **`band` 为 null、`scoring_points` 为空**，结构化内容只在 `raw_text` 里。
   该形态在 `test_campus_flow.py` 的初版回放中被实测命中（用例已按 schema 正确回放），T12 的
   CERT 主观题批改与前端结果卡必须能渲染"无得分点结构 + 原文回退"这一态。
4. **实现自检发现的边界口径**：`attempt` 的 `score` 在 band 类题型落 15 分制档位分、在评分点题
   型留空（`max_score` 同步留空）——若两列混用不同量纲，后续 CET-12/CERT-15 的聚合会失真；
   已按 06 §2.1 的"15 分制原始分"口径固定并有断言。

## 6. 移交 T10-T14 的接口要点

1. **端点追加方式**：在 `build_campus_router` 内继续以 `@router.<method>("…")` 注册，写端点用
   `Depends(guard.get_writable_profile)`，子资源用 `guard.scoped_row(table, row_id, profile.id,
   missing_code="…")`（`FORBIDDEN_PROFILE` 与"不存在"两态已由守卫区分）。service 侧新增方法直接
   加到 `CampusService`，异常用 `CampusError(code, message, **extra)`，新码先入 `ERROR_SPECS`。
2. **AI 端点统一走既有链路**：模型选择用 `CampusService.model_for_task(task)`（已含设置面板 >
   config.toml > 当前默认模型 > 静态推荐），provider 用 `ManagerGrader` 同款方式从 `manager.provider`
   取；失败映射按 T07 §6-6。切勿在端点内另起 `ProviderClient`。
3. **E5 未做的两件事**（D 组接手）：① 客观题判负后写 `mistake_book`（按 `(profile_id, question_id)`
   UPSERT、`wrong_count` 递增，且需显式填 `last_wrong_at`——`store.insert` 不会自动补该列）；
   ② 答对/答错后的 `review_queue` 间隔推进（T13 的 `review_scheduler`）。
4. **`store.insert` 的自动补列**只有 `id`/`created_at`/`updated_at`；`source_doc.imported_at`、
   `mistake_book.last_wrong_at`、`cert_deadline`/`weekly_report` 的日期字段等都要显式落值。
5. **可复用的现成能力**：`CampusService.attempt()`（C2 回看）、`question_payload`/
   `attempt_payload`/`task_payload`/`profile_payload`（JSON 列解码口径统一）、`_call`/`_async_call`
   （错误翻译）、`parse_questions`（E1）、`_judge`（客观题判分）、`ModelInventory`（能力自检）。
6. **前端契约注意**：A1/G1 的列表不套分页信封（`{items}`），E2 套 `{items,total,page,page_size}`；
   `degrade_level>=1` 时 `grading_json.notice` 非空必须渲染；得分点制题型的 `band` 为 null（§3.2-3）。
7. **不要改 `ss/server/app.py`**：挂载已在 `main`；本阶段实测 T06 的预算用例会拦住任何表外改动。
