## 3. 测试与验证

### 3.1 证据一致性校验（TDD，27 用例全绿）

先写测试（RED：校验模块缺失，collection error）后实现（GREEN）。用例分四组，覆盖核心流程、异常输入（篡改证据/缺文件/格式异常）与边界场景（门槛恰好相等、样本数下限、调用预算上限）：

| 组 | 覆盖 |
|---|---|
| `TestT01Evidence`（10 例） | 真实矩阵正向校验（80 格、每格 ≥20 样本、L0 98.75% ≥60%、L0+L1 ≥90%、fail/L3 为 0、调用 ≤5 次预算、response_format 0 拒绝、分布与比率自洽、一致性 10/10 档位相同且零降级）；篡改负例：fail_count=1、L0 低于门槛、calls_max=6 超预算、缺格、缺文件、一致性档位不一致、一致性带降级 |
| `TestT03Evidence`（6 例） | 真实冒烟证据正向校验（11 项检查与登记表精确一致、鉴权 401/200/401、mtime 前后相等、退出码 0）；篡改负例：all_pass=false、缺检查项、翻转检查项、mtime 变化、spike 标识错误 |
| `TestT02Doc`（5 例） | 交付文档量化表正向解析（验收行 5 条全部"达标"、实测值 ≥ 同行门槛、no_text_layer 与零切片结论在档）；篡改负例：判定翻转为"未达标"、实测改到门槛之下（75% < 80%）、删除扫描件结论、缺文档 |
| `TestT04Report`（6 例） | 报告要素机器校验：最小合规报告正向通过；负例缺 OCR 决策、缺缩减判定、缺 GRADING_START_LEVEL、缺 top6 指标、缺报告文件；真实报告用例在报告落盘后自动启用 |
