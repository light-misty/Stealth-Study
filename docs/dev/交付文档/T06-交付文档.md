## 4. 挂载与守卫设计说明

### 4.1 挂载形态（侵入点 #9，03 §2）

```python
    app = FastAPI(title="coworker", version="0.0.0", lifespan=lifespan)
    from ..campus.routes import build_campus_router
    app.include_router(build_campus_router(manager))
```

- 函数体内相对导入，与 `app.py` 现有 30 余处函数级 import 风格一致；`ss/server/run.py` 的入口是 `ss.server.run:main`（`python -m` 语义），不存在 `__main__` 包外相对的失败场景。
- `build_campus_router(manager)` 构造即 `CampusStore()`（`state_dir()/campus.db`），迁移在挂载时执行；迁移失败 → `include_router` 抛异常 → 应用启动失败（03 §2-4、02 §3.4）。`test_mount.py` 以 `SchemaVersionError` 固定该行为。
- campus 端点**不加入** `tokenless_paths`，自动继承既有 sidecar token 中间件（03 §1）；`test_mount.py` 断言无 token/错 token 401。

### 4.2 错误体助手

- `ERROR_SPECS` 是 03 §6 的机读镜像（33 码）+ 03 §4 端点表中使用但 §6 漏列的 4 码（`FORBIDDEN_PROFILE`/`ASSESSMENT_NOT_FOUND`/`ITEM_NOT_FOUND`/`NO_TASK_DATA`，见 §6-3）。
- `error_detail(code, message=None, **extra)` 产出 `{"code", "message", "retryable"}`，可附加字段（如 `PARSE_ERROR` 的行号）而不改变形状；`campus_error` 返回 `HTTPException(detail=dict)`，与 03 §1「campus 全部用它返回结构化错误，与既有路由（detail 为字符串）向后兼容」一致。
- 表外码一律 `KeyError` 快速失败，杜绝"拼错码却拿到看似合理的状态码"。

### 4.3 `ProfileGuard`（profile_id 横切）

| 方法 | 语义 | 拒绝码 |
|---|---|---|
| `requested_profile_id(request)` | 按 path（`{pid}` 或 `{profile_id}`）→ query → JSON body → form 的顺序取首个非空值；空串/纯空白视为未携带 | — |
| `load(profile_id)` | 单次主键读；未命中 | 404 `PROFILE_NOT_FOUND` |
| `get_profile(request)` | 需档案端点的统一依赖，注入 `ExamProfile` | 400 `PROFILE_REQUIRED` / 404 `PROFILE_NOT_FOUND` |
| `get_writable_profile(request)` | 写端点依赖；在 `get_profile` 之上追加状态守门 | 409 `PROFILE_READ_ONLY`（仅 `finished`） |
| `scoped_row(table, row_id, profile_id, *, missing_code)` | 子资源读取：先 `get_scoped`（`WHERE id=? AND profile_id=?`），越界命中 0 行；再以主键探测区分"他人所有"与"不存在" | 403 `FORBIDDEN_PROFILE` / `missing_code`（404 族） |

要点：

1. 端点侧只写 `Depends(guard.get_profile)`，拿不到裸 `profile_id` 字符串——07 §4「禁止端点内裸收 `profile_id` 字符串直查」由签名形状保证。
2. `scoped_row` 的两次查询是有意为之：`get_scoped` 是数据层的 `WHERE profile_id=?` 双保险（01 §3），随后那次主键探测只回答"这个 id 是否存在"，用于区分 403 与 404；不这样做，03 §6 的 `ATTEMPT_NOT_FOUND`/`DOC_NOT_FOUND`/`QUESTION_NOT_FOUND`/`POINT_NOT_FOUND`/`MOCK_NOT_FOUND`/`ASSESSMENT_NOT_FOUND`/`RQ_NOT_FOUND` 七个码将永远不可达。
3. body 解析对异常一律降级为"未携带"（非法 JSON、非对象、非字符串、不可解析表单），最终归到 400 `PROFILE_REQUIRED`，不产生 500。

## 7. 移交 T09（`service.py` 全局域端点）的接口要点

1. 端点依赖：需档案的写端点用 `Depends(guard.get_writable_profile)`，读端点用 `Depends(guard.get_profile)`；子资源用 `guard.scoped_row(table, row_id, profile.id, missing_code="...")`，`missing_code` 取 03 §6 中该组的 not-found 码。
2. 错误一律 `raise_campus_error(code, message=None, **extra)`；新码先入 `ERROR_SPECS` 再使用（表外码会 `KeyError`）。
3. `build_campus_router` 内已持有 `campus_store` 与 `router`：T09 在此追加 `CampusService(campus_store, campus_config)` 并注册 A/E/G1 组端点；不要在其它模块另开 `CampusStore`（02 §2.1 单例）。
4. `manager` 参数留给 T13 的自动化模板（经既有 TaskStore CRUD），campus 不读写 `coworker.db`。
5. `guard.scoped_row` 现支持"他人所有 → 403"与"不存在 → 404"两态；若某端点的 03 契约要求不分态，需显式传同一 `missing_code="FORBIDDEN_PROFILE"` 并在 03 文档登记。
6. **给 T08 的提醒**：`source_doc.imported_at` 既无 DDL 默认值，也不在 `store.insert()` 自动补的 `created_at`/`updated_at` 名单内，导入路径必须显式落值（本阶段用例已实测该约束）。
