### 3.3 关键用例要点（异常输入与边界场景）

- **知识点树**：空标题/纯空白标题拒绝建点且不调用 H2；建点失败表单保持打开、错误呈现、树形状不变；三层为深度上限（depth 3 的行不再出现子级添加入口）；空树给 empty 态 + 建根入口；删点后 refetch 计数断言（H1 恰好 2 次）；H5 失败保留旧档位；本地已设档位在覆盖率刷新后不被 weak_top5 播种回滚。
- **主观题批改**：空作答客户端拒绝不调 C1；C1 失败（409 不可重试）保留作答内容与表单、无结果卡、无重试钮；C1 超时（可重试）出重试钮且重试复用当前表单值；请求在途期间提交禁用 + 钩子层同步 busy 防重（双击只发一笔）；三档徽标按 dimensions 顺序 1/0.5/0 → hit/partial/miss。
- **考试节点**：六类节点全量出现在表单；缺日期客户端拒绝不调 H7；`DUPLICATE_NODE` 呈现既有文案且表单值保留；时间轴行 `data-tier` 三档抽验（35 天 normal / 5 天 d7 / 1 天 d1）；未建提醒节点出 H9 按钮、已建节点只显示状态；空节点列表给 empty 态；加载失败可重试。
- **工具层**：`deadlineTier` 覆盖 -1/0/1/7/8/30/31 及 NaN；`scoringStateOf` 覆盖 1/0.5/0、NaN、max=0、负分（异常输入一律 miss，不抛错）。

### 3.4 开发中发现并修复的问题

1. **钩子返回类型与组件契约不符**（T19.3 内发现）：`addPoint` 原返回 `KnowledgePoint`，面板与测试需要可递归渲染的节点 → 钩子内构造 `{...created, children: []}` 返回 `KnowledgePointNode`。
2. **测试闭包 TS 收窄为 `never`**（T19.3）：`let x: T|null` 赋值后访问属性被收窄 → 改用数组捕获模式（`captured.push(await ...)`）。
3. **门禁 glob 不含子目录**（T19.7 修复）：T16 的 `layering.test.ts` 扫描 `../*.tsx` 不含 `cert/`，三组件此前不受四项分层检查约束 → 扩展为 `../**/*.tsx`，legacy api 检测同步扩到任意深度（`(?:\.\./)+api`），扩展后全量重扫通过。
4. **推送被 schannel 吊销检查阻断**（环境问题，非代码）：统一改用 openssl + 本地 CA 参数推送（§1.3）。

1. **`DeadlineBanner` 未新建组件**：07 §5 T19 将 `DeadlineBanner（D-30/D-7/D-1 视觉分级）` 列为本阶段新增文件，但该组件已在 T16 作为三台共享组件交付并挂在 cert 台顶部（`TRACK_BANNERS.cert`）。本阶段的落实方式是**升级既有共享组件**（加 `data-tier` 透传 + 档位样式），而非另建同名组件造成二义。验收点 ② 的实质（三档状态与 snapshot 一致）不受影响。
2. **档位数对齐后端实现而非文档三档**：07 写三档（D-30/D-7/D-1），后端 `reminders.py` `deadline_view()` 实际返回六档（normal/d30/d7/d1/today/overdue）。前端样式表覆盖全部六档（today/overdue 亦有明确视觉），避免响应落在文档未列的档位时丢样式。
3. **得分点三态的还原路径**：C1 响应**不含**原始 `scoring_points` 数组——后端把得分点映射为 `dimensions`（score ∈ {1, 0.5, 0}，max=1，`ss/campus/service.py` `SCORING_POINT_SCORES`）。前端以 `scoringStateOf(score, max)` 从 dimensions 还原 hit/partial/miss。**T12 交付文档中"响应附带 scoring_points"的表述与实际代码不符**，以实现为准；若后端未来要回传原始得分点元数据，属增量契约。
4. **掌握度状态无全局 GET**：H1 知识树不含每点 level，也不存在按 profile 全量读掌握度的端点。前端维护 `levels` map：H6 `weak_top5` 播种 + H5 写成功回显 + 本地已设集合（ref）防覆盖。**无记录的知识点不渲染掌握度点**（避免把"无数据"伪造为"unknown"）；需要全量掌握度回显时，依赖用户逐点交互或后端补端点。
5. **H2 改名/改描述与 H4 生成知识树未接 UI**：`patchKnowledgePoint` / `generateKnowledgeTree` 在 api 层已具备（T15），本阶段面板未提供入口（07 §5 T19 清单未含）；`campus.cert.tree.generate` key 沿用 T16 预留、仍未消费，死 key 反向扫描按 08 §8 归 T22。
6. **`useGrading` 无独立 hook 级测试文件**：与 T19.3 三个钩子有 `cert-hooks.test.ts`（16 例）不同，`useGrading` 的行为（提交参数、busy 防重、失败保形、可重试）由 `SubjectiveGradingPanel` 9 例全量覆盖，未重复建测试文件。
7. **H9 提醒与 H3 删除均无确认弹窗**：一键提醒单击即发（重复点击有本地 busy 防抖；重复建提醒的幂等性依赖后端 H9 返回 `automation_ids`），删除节点单击即发且**不可逆**（无回收站概念）。若需要确认交互属后续 UI 增强，当前与 04 §3.2 的最小交互描述一致。
8. **掌握度"勾选"实现为三档按钮**：04 §7.4 的"勾选联动"没有指定具体控件形态；实现为每行三档按钮（点击即写 H5，当前档位高亮），数据流与验收一致。主理人若偏好弹层/长按等形态，属展示层调整。
9. **pytest 未重跑**：本分支 `git diff` 全部 18 个文件位于 `surfaces/gui/`，零 Python 改动，pytest 输入与基线**字节级相同**（T16 交付文档 §5-11 已做过两树字节级对照并登记先例），重复执行不产生信息量，故省略。
10. **未做视觉走查**：同 T16 §5-13，本阶段只保证类型检查与测试通过；样式复用既有 token（`warnInk/warnSoft/danger/dangerSoft/ok/okLine/accent/panel/line/rounded-xl2`），未引入新样式依赖。
11. **测试环境 i18n 仅有英文资源**：`test-setup.ts` 既有约定，全部断言走 testid 不依赖文案；中文文案质量未经人工审校，key 覆盖由门禁保证。
12. **jsdom 无真实布局**：树的层级缩进用行内 `marginLeft` 计算，仅保证 DOM 结构与 data 属性正确，像素级缩进未验证。
