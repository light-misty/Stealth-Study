### 3.3 关键用例要点（异常输入与边界场景）

- **定级测评**：草稿丢失（404）清 key 回开始态；题目缺 payload 渲染 `question-missing` 且不打断整卷；交卷失败错误可重试且按钮仍在；已完成的存量测评直接显示存量分（不再触发 F4）；`MODEL_NOT_CONFIGURED` 显示错误且不出卷。
- **词汇**：F7 失败回滚到点按前的掌握度（并非简单回退 UI 状态——回滚目标是「该词此前值」）；助记失败按钮恢复可用可重试；空日给 empty 态。
- **听力**：客观题判错也展示标准答案；主观题以 `is_correct == null && score != null` 区分，显示得分与同步批改提示；提交失败保持作答可编辑；答题进度 `第 x/N 题`。
- **批改**：空文本禁提交；在途禁提交；失败 retry 重放同一提交；历史按 kind 过滤（essay/translation 各自独立）；打开历史项走 C2 展示档位得分与提交原文。
- **模考**：`remaining_seconds` 以服务端值为初值逐秒递减；暂停/恢复上报暂停秒数（F13，`Math.max(0, round((now-pausedAt)/1000))`）；快进钩子仅 dev 构建渲染；恢复已消失的模考（任意失败）清 key 回开始态；阶段草稿按 `ss.campus.cet.mock.<examId>.<stage>` 持久化，卸载重挂后恢复。
- **台面壳**：CET 面板全部挂载（测评开始按钮、词汇空态、听力空态、两个批改输入区、模考开始按钮、老毛病卡同时可见）；kaoyan/cert 台不受影响。

### 3.4 开发中发现并修复的问题

1. **T15 api.ts 与 T10 后端的三处契约缺陷**（`c37a209`、`74bf770`）：① F3 `patchAssessment` 请求体缺必填 `profile_id`（后端 `AssessmentPatch` `extra=forbid`，联调必 422）；② F13 `pauseMockExam` 缺 `{seconds}`（后端 `MockPause` 同）；③ F7 `setVocabMastery` 缺 `profile_id`（后端 `VocabPatch` 同）。三处均在实现组件前以 api 层测试先行修复，签名变更同步了全部调用点（当时无其他调用方）。
2. **T10 文档化类型与实际响应的偏差**（`c37a209`）：`MockSectionScore/MockSubmitResult` 实为 `{earned,max,ratio}`；F4 `gap_table` 行实为 `{section,current,target,gap}`；F11/F13 返回派生视图 `MockExamView`（`remaining_seconds/stage_expired/server_now`）；F2/F11 的 assessment payload 含 `questions` 数组（剥离答案）；E5 客观题返回 `pending_grading + standard_answer`。均已落进 `campus/types.ts`。
3. **测试环境 i18n 为 en**：`test-setup.ts` 装载英文资源，组件文案断言须用英文；面板 smoke 测试初版用中文标题断言失败后已修正。
4. **`MockExamConsole` 缺根 testid**（首版实现遗漏）：7 个用例红（`campus-mock-console` 不存在）；补在 ongoing 相外层容器。
5. **`Date.now` mock 被框架内部调用消耗**：`mockReturnValueOnce` 队列被 React/RTL 内部调用吃掉导致暂停秒数为 0；改为 `mockReturnValue` 分阶段切换（暂停前后两个固定值）。
6. **`vi.restoreAllMocks()` 位置**：模考用例依赖 `Date.now` spy，在 `beforeEach` 统一 restore，避免泄漏到其他用例。

1. **三处请求体缺陷属上游遗漏，本阶段修复**：T15 交付的 `api.ts` 中 F3/F13/F7 缺后端必填字段（§3.4-1）。这三处若直接联调必然 422；本阶段在实现组件前修复并补了 api 层测试。此为对既有交付物的修正，非本阶段新功能。
2. **模考作答区是本地草稿，未接 E5 逐题作答**：F11 模考读取不返回题目 payload（T10 契约即如此），故 `MockExamConsole` 的三个作答区是自由文本草稿（localStorage 持久化），不产生 attempt 记录；F14 的 `estimate_score/by_section` 完全由后端按其自身数据估算。若后续产品要求模考逐题作答，需后端在 F11 返回题目并在前端补 E5 打通——当前实现满足 07 §5 T17「阶段计时 + 收卡锁定 UI」的字面范围。
3. **模考结果页的 by_section 仅交卷当次可见**：F14 响应含 `by_section`，但 F11 对已提交模考不返回分项数据，刷新后结果页只显示 `estimate_score`。若要求持久查看分项，需后端提供只读端点或前端 sessionStorage 缓存（后者是伪持久化，未做）。
4. **C3 历史回看是摘要级，不是完整批改卡**：C2 返回的 `grading_json` 是后端内部白名单格式（`dimension_scores` 为 dict、errors 为引擎原始格式），与 C1 响应的 `{dimensions[], errors[]}` 形状不同；前端做格式适配会依赖引擎内部字段结构，脆弱且等于把后端映射逻辑复制到前端。故历史回看展示档位得分、提交原文等 attempt 摘要。四段完整批改卡只在 C1 当次响应后展示（验收①本身满足）。
5. **测评/模考的「进行中」状态依赖 localStorage**：后端无「列出进行中测评/模考」端点，前端按 profileId 存 `ss.campus.cet.assessment.<pid>` / `ss.campus.cet.mock.<pid>` 记录 id；换浏览器/清存储后无法自动找回进行中的测评（F2 404 后回开始态，会产生一份新测评，旧测评成为孤儿数据）。此为端点缺失下的务实取舍，已用 404 清理兜底。
6. **暂停语义按「上报暂停时长扣除」实现**：F13 `{seconds}` 的语义是补记暂停时长以重算 deadline；前端在恢复时上报。暂停期间倒计时停止，但不做「暂停中禁止查看题目」之类的强管控（后端本就不依赖前端作答）。
7. **快进钩子同时带 `data-testid`**：08 §7 要求 dev-only `data-hook="fast-forward"`；为单测定位方便同一按钮加了 `data-testid="fast-forward-hook"`。该元素整体在 `import.meta.env.DEV` 为假时不渲染，生产构建（`npm run build` 实测）不含它。
8. **词汇掌握度值域**：03 文档 F7 写 `known|fuzzy|unknown`，后端列存 `unknown|fuzzy|mastered` 且两者都接受（`VOCAB_MASTERY_ALIASES`）；前端统一发送并展示列形式三档（`不认识/模糊/已掌握`）。
9. **听力题按 `subject=listening` 拉取**：E2 过滤参数与后端 `SUBJECT_STAGE` 映射一致；题库为空时给引导文案（「先去导入题库或生成题目吧」）。E1（录题）不在 T17 范围。
10. **幂等键仍未在写路径传递**：与 T16 §5-12 同一事项——`createAssessment/createMockExam/importVocab` 的 api 封装支持 `Idempotency-Key` 第三参，但 T17 未生成并传递幂等键。当前以「按钮在途禁用」兜底（测评 start、模考 start、批改提交、模考推进/交卷均有 busy 锁）。
11. **未做浏览器视觉走查**：只保证类型检查、单测与生产构建通过；Tailwind 类名复用既有 token，未引入新样式依赖。jsdom 无法验证的滚动定位（`scrollIntoView`）未实现——续做定位以 `data-resume-target` 属性标记承载，e2e 阶段可按需补滚动。
12. **组件内两处运行时拼接 i18n key**（`section_${section}` / `stage_${stage}`）：`section_listening/reading/writing_translation` 与 `stage_writing/listening/reading_translation` 家族双侧齐备，`layering.test.ts` 的 key 家族断言覆盖；若后端将来返回新 section/stage 枚举值，界面会裸显示 key，需同步补文案。
13. **组件交付数与任务清单的对应**：07 §5 T17 列 7 个组件；本阶段实际新增 8 个源文件（多出的 `GradingWorkshopBody` 是作文/翻译两面板的共享主体，避免两份相同的作答-历史流程代码），并在 T17-7 一并挂载。07 的清单不含它，特此说明。
