### 3.3 关键用例要点（异常输入与边界场景）

- **倒计时**：`examDate` 为 null / `""` / 非日期串 / `2026-02-31`（合法格式但不存在）一律返回 `null` 不渲染；过往日期不显示负数天数，改显示"考试日期已过"；同一天为 0 天并高亮。
- **SM-2 阶梯**：连对 1/2/3/4/5 次 → 1/2/4/7/15 天，第 6 次起封顶 15；答错、0 次、负数、`NaN` 一律回落 1 天。
- **建档卡**：空标题与纯空白标题拒绝提交并给出 `campus.profile.title_required`；可选字段留空则不出现在请求体（不传 `""`）；`target_score` 填 `abc` → 转 `undefined` 而非 `NaN`；请求在途期间提交按钮禁用（`busy`）。
- **错题本**：1000 条数据只挂载窗口内行；归因改判失败时回滚选项并提示，行不消失；空列表给出 empty 态而非空 ul。
- **复习队列**：提交后乐观移除，失败则还原并提示；`payload` 缺 `word/title` 时回落到 `item_id`/`id`，不渲染 undefined。
- **批改卡**：`errors` 为空给"本次未检出错误"；`offset` 为 null 的条目不提供定位入口；未传 `onAddToMistake` 时不渲染该按钮。
- **资料库 / 问答**：文件选择后清空 input（允许重复导入同一文件）；仅 `failed` 文档出现"重新解析"；空问题不发请求；问答失败清空上一轮答案并提示；引用按钮带 `data-doc-id` / `data-page-no`。
- **台面壳**：档案列表请求 pending 时渲染骨架；失败且 `retryable` 时给重试按钮；无档案时只渲染引导卡；三台面板按配置挂载（KY 含资料库 + 问答，CET/CERT 仅共享两面板）。

### 3.4 开发中发现并修复的问题

1. **重复建档**（`e1f3aa3`）：建档请求在途期间再次点击提交会 POST 两次 A2（前端未生成幂等键）。修复：`ProfileCreateCard` 增加 `busy`，在途期间禁用提交并直接 return。
2. **`layering.test.ts` 引入 node 内置模块导致 `tsc` 失败**（`0554ef1` 内修复）：改用 `import.meta.glob(..., { query: "?raw" })` 读取源码，避免新增 `@types/node` 依赖（04 §1.1 要求不引入新依赖）。
3. **`import.meta.glob` 相对路径错一级**：`../../campus/*.ts` 实际指到 `components/campus`，扫描集为空 → 断言"扫描到源文件"先红后修正为 `../../../campus/*.ts`（这条 RED 正是为了防止门禁静默空转）。
4. **`CampusProfileContext` 未使用变量**（`2a08aca` 后续修）：`tsc` `noUnusedLocals` 报错，去掉多余解构。
5. **库面板 retry 的 id 不匹配**（测试期内发现）：`retryLibraryDoc` 返回对象的 id 必须与被替换项一致，否则列表不更新——已在用例中用同 id 固定，实现按 id 精确替换（不追加）。

## 5. 与文档的差异登记

1. **组件命名以 07 为准**：07 §5 T16 列 `ReviewQueuePanel` / `LibraryPanel` / `QAChatPanel` / `CountdownBanner` / `DegradeBadge` / `ProfileCreateCard`，而 04 §1.2/§3.2 写 `ReviewQueueCard` / `LibraryQA`。本阶段按 07（并注明"04 §3 组件表为准"）落地为 `ReviewQueuePanel` 等；`ReviewQueuePanel` 同时支持 `dueItems` 受控传入，兼容 04 §3.2 的 `{ dueItems, onResult }` 契约。
2. **新增 `campus.model.*` 段**：04 §7.2 的 key 树没有 `model` 段，但 `EmptyModelGuide`（A8）需要"未配置 / 能力不足 / 某功能不可用"三组文案，故新增 `campus.model.{empty_title,empty_hint,partial_title,partial_hint,unavailable,task.*}`；另补 `campus.common.{loading,retry,error,exam_passed}` 与 `campus.cert.deadline.node.*`（6 个节点名，避免把 `admission_ticket` 之类的枚举直接显示给用户）。
3. **KY 顶部横幅**：04 §2.1 给考研台画的是"四轨完成度"，该面板属 T18 `ProgressDashboard`；T16 用 `CountdownBanner`（`exam_date`）兜底三台顶部。若主理人坚持 KY 顶部只放完成度，改 `TRACK_BANNERS` 一行即可。
4. **三台面板配置**：`TRACK_PANELS` 中 `kaoyan` 挂资料库 + 问答（依据 04 §2.1 K3），`cet` / `cert` 只挂共享的错题本 + 复习队列；T17-T19 在各自条目追加业务面板即可，无需改逻辑。
5. **归因改判交互**：04 §3.2 写"归因标签点击改走 D2"，实现为下拉选择（一次点击即确定目标归因，避免循环点击误改），仍走 D2 `patchMistake`。
6. **`pollDocReady` 增加 40 次上限**：04 §8 只说"读到 ready/failed 即停"；为防止后端长期停留在 `pending` 导致无限轮询，加了 `maxAttempts=40`（约 60s）兜底，接口默认参数可覆盖。
7. **面板自取数据**：`MistakeBookPanel` / `LibraryPanel` / `QAChatPanel` 按 `profileId` 自取数据（与 04 §8"各台面板自取自身数据"一致），`ReviewQueuePanel` 额外支持受控 `dueItems`（不触发请求）。
8. **虚拟滚动的视口兜底**：jsdom 拿不到 `clientHeight`，组件在测不到视口时按 420px 计算窗口（`ceil(420/72)+4 = 10` 行），浏览器内以真实 `clientHeight` 为准；行高固定 72px 是窗口算术的前提。
9. **`CampusSection.tsx` 未在本阶段实现**：04 §1.2 把它列在 `components/campus/` 下，但 07 §5 T16 的清单不含它，且其挂载点（设置页 campus tab）属 T20 侵入点 #4-#6。建议在 T20 一并交付；若主理人要求 T16 补，属新增约 1 个组件的工作量。
10. **死 key 反向扫描未做**：08 §6.2 ②（zh.json 定义 ⊆ 引用 ∪ 白名单）依赖 T17-T19 组件全部落地后才有完整引用集合，按 08 §8 归 T22。本阶段只做了 ①（引用 ⊆ 定义）。
11. **pytest 对照结论**：本分支零 Python 改动，pytest 输入与基线字节级相同。实测两侧进度标记 3047 字符，差异恰为 `test_mount.py` 那两条"基线预算"用例（基线 skip、分支通过），`F` 位置与数量完全一致（各 20 个，均为 `v0.0-spike-report.md` §7-5 已登记的既有失败）。**分支未让任何既有用例由绿转红，也未让任何既有用例由 skip 转 fail**（反向的两条 skip→pass 是 `test_mount.py` 自身按修订判定的设计行为）。注意：本机删除守卫会打断 pytest 临时目录回收，两棵树的 summary 与 `-rf` 的 FAILED 列表都不打印（`grep -c "^FAILED"` 为 0 属正常），故结论以进度标记逐字符比对为准。
12. **幂等键（03 §1 `Idempotency-Key`）仍未在写路径传递**：`createProfile` / `importLibraryDoc` / `retryLibraryDoc` 的 api 封装已支持第三参数，但 T16 未生成并传递幂等键（未检索到该事项的任务认领）。当前以"提交按钮在途禁用 + 后端 A2 `DUPLICATE_TITLE` 409"兜底。若主理人要求落实，改动面是这三个调用点各加一个稳定键。
13. **未做视觉校验**：按项目约定，本阶段只保证类型检查与测试通过，未在浏览器中做像素级视觉走查；Tailwind 类名复用既有 token（`panel` / `line` / `warnInk` / `accent` / `rounded-xl2` 等），未引入新样式依赖。
