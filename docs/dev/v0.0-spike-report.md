## 1. T01 量化结论（批改 JSON 输出成功率）

矩阵：20 篇真实四六级作文 × {`mimo-v2.5-pro` 强模型, `mimo-v2.5` 便宜对照} × {L0 裸 prompt, L0+`response_format`} = 80 格，每格 20 样本。

| 指标 | 门槛（08 §3.1） | 实测 | 判定 |
|---|---|---|---|
| 每格样本数 | ≥20 | 4 格 × 20 = 80 | 达标 |
| **L0 成功率**（`degrade_level=0` 占比） | **≥60%** 否则 `GRADING_START_LEVEL=1` | 合计 **98.75%**（79/80，Wilson 95% 下界 93.3%）；最差单格 95% | **达标** |
| **L0+L1 合计成功率** | **≥90%** 否则加模型能力前置提示 + CERT 主观题降 P1 | 合计 **98.75%**（下界 93.3%） | **达标** |
| L0+`response_format` 对比组 | 记录增量，不作门槛 | 40/40 被端点接受、0 拒绝；相对裸 prompt 增量 **−2.5pp**（无增益） | 已记录 |
| 批改一致性（PRD CET-09） | 10 篇 × 2 次，≤1 档 | **10/10 档位完全一致**（最大分差 0 档），全部 `degrade_level=0` | 达标 |
| 抽检人工评分相关性 Kendall tau | 不设硬门槛 | **不可计算**（公开语料无人工档位标注） | 不适用 |

补充事实：L3 与失败均为 0；单格调用全部 ≤5 次预算；唯一一次降级（E18）完整走通 L0→L1→L2 链路并在预算内收敛——降级链本身被真实失败形态验证有效。档位存在 1 档级运行间波动（E07 同条件矩阵 11 / 复跑 14），PRD CET-09 的 ≤1 档容差恰好覆盖。

## 4. 三项决策（逐条落字）

### 决策一：`GRADING_START_LEVEL` 取值 —— **保持默认 0**

- **依据**：T01 实测 L0 成功率 98.75%，远超 60% 门槛；L0+L1 = 98.75%，同样远超 90% 门槛。06 §8-3 预留的一行常量不需要改动。
- **生效动作**：T07 落地 `grading.py` 时 `GRADING_START_LEVEL = 0` 为默认值，并保留常量可配（新厂商模型接入前按 T01 §9-6 重跑 spike 后再调整）。
- **边界条件（必须随决策执行）**：本结论仅在 MiMo 两个模型上实测，**不能外推到其他厂商**——V0.1 接入任何新厂商模型前，须先用该厂商模型重跑 T01 spike，L0 成功率 <60% 时对该厂商单独把起点调到 1。

### 决策二：无书签 PDF 的 L1/L2 分流 —— **确认"书签优先、文本行兜底"，抽取失败自然分流 L2**

- **依据**：无书签文档标题抽取成功率 81.1% ≥ 60% 门槛，L1 对该类文档**可用**；但实测同时证明两件事：① 只放宽正则不够——relaxed 口径下运行页眉会把目录污染到 ≈1 条/页，L1 命中率从 90% 掉到 30%；② 编号式标题（"2.1 xxx"）在 spec 正则下 0% 命中。
- **生效动作**（T08 落地 `library.py` 时执行，全部为 T02 §7 已验证的实现，无新设计）：
  1. 目录来源采用 **PDF 书签优先、文本行兜底**（`--toc-source outline` 口径，命中率 90%）；
  2. 标题行正则放宽为容忍空白（`第\s*[一二三四五六七八九十百零\d]+\s*[章讲部分节篇]`）并追加编号式分支（`^\s*\d+(\.\d+)*\s+\S`），同时叠加"同一标题 stem 出现在 ≥3 个不同页面视为运行页眉"过滤；
  3. 目录清单做**最短标题门槛（规范化后 ≥4 字符）**，过滤书签伪目录项（附录单字母项击穿包含匹配的实测缺陷）；
  4. 章节跨度计算对"下一项与当前项同页/过近"的塌缩情形回退（更大层级条目或文档末页兜底）；
  5. `section_title` 抽取失败的文档 `section_title=NULL`，**自然分流走 L2**（06 §4.2-3 已覆盖，无需新代码）；L1 限域召回为空时回退全库 L2，`used_retrieval` 如实标记。
- **附带确认**：L1 章节路由 prompt（06 §5.2）方案成立——真实模型路由命中率与确定性路由持平（90%）、端到端召回显著更好（0.8 → 0.95），T08 可直接沿用。

### 决策三：OCR 是否立项 V0.2 —— **V0.1 维持不立项，登记为 V0.2 候选，由真实使用数据触发再议**

- **依据**：T02 扫描件（1/5 语料）实测 57/57 零文字层，判空分支完整生效（`no_text_layer` + 产品级提示路径成立）；而 06 §6.3 的成本判断不变——PaddleOCR 需捆绑数百 MB 推理运行时、Tesseract 需系统级安装，桌面应用分发不可控。技术验证**没有产生必须引入 OCR 的证据**，缺口在产品层用"扫描件请配合 OCR 工具转文字版（支持 TXT/MD）"的提示覆盖。
- **生效动作**：V0.1 不引入任何 OCR 依赖（06 §1 依赖边界不变）；T08 的导入失败提示按上述文案落 i18n。
- **再议触发条件（量化，供 V0.2 规划）**：V0.1 上线后统计"扫描件导入占比"（`parse_status=failed` 且 `fail_reason=no_text_layer` 的导入次数 / 总导入次数），连续两周 **>20%** 且伴随用户流失信号时，将 OCR（建议 PaddleOCR 移动端模型，仅本地推理）提为 V0.2 首个评审项；否则继续以转文字提示覆盖。

> 三项决策均为建议决策，**待主理人在决策门评审时拍板**；拍板通过即按"生效动作"进入 T05，任何一项被推翻只需修订对应条目，不影响 T05/T06 的任务结构（07 §7 范围红线）。

## 5. 范围缩减建议判定

08 §3 各门槛的处置预案逐条核对：

| 预案 | 触发条件 | 是否触发 |
|---|---|---|
| `GRADING_START_LEVEL=1`（批改默认 L1 起步） | T01 L0 < 60% | **否**（98.75%） |
| 批改端点加模型能力前置提示（`EmptyModelGuide`）+ CERT 主观题批改降 P1 | T01 L0+L1 < 90% | **否**（98.75%） |
| rubric prompt 加"先摘证据再定档"两步指令重测 | 一致性低于 PRD CET-09 口径 | **否**（10/10 一致） |
| 章节 prompt 加目录行号锚定重测 / L1 仅限书签完整文档 | T02 L1 命中率 < 80% | **否**（90%） |
| 关键词 2-gram 调参 / top_k 提至 8 | T02 top6 < 70% | **否**（85%；且实测 top_k=8 在端到端口径无提升，该预案不作首选） |
| 无书签文档 `section_title=NULL` 强制分流 L2 并记 V0.1 已知限制 | T02 标题抽取 < 60% | **否**（81.1%，但§4 决策二仍吸收了该预案的自然分流机制） |
| 检查切片/章节归属策略，问题清单入本报告 | T02 可用率 < 70% | **否**（80%） |
| try/except 包裹挂载，#9 风险升级重新评审 | T03 任一项不过 | **否**（11/11 PASS） |

**结论：V0.1 范围缩减建议不触发，V0.1 按 PRD P0 原范围进入 T05。** 唯一需要带入 V0.1 的范围级注意项是 T01 的单厂商限制（决策一边界条件），属"新增模型接入前的重跑规程"，不缩减现有范围。

## 6. 移交 V0.1 的实施注意事项（决策附带的工程约束）

以下条目来自三份 spike 的实测发现，**已由决策吸收为 T05-T08 的实施约束**，V0.1 各任务验收时逐条核对：

1. **T05/T08（数据层/资料库）**：为资料库场景单独设定解析上限（1-2 MB 字符或"已含全部章节"判停），与 `attachments.MAX_TEXT_CHARS` 会话内附件口径解耦（T02 §7-3：775 页教材仅前 44.5% 入库不可接受）。
2. **T07（批改引擎）**：沿用 T01 固化的 `BAND_INTERVALS` 档位区间表、`_extract_json` 严格语义（不做激进修复）、L1 的 8 行错误槽位模板；rubric 一致性测试须先归一化空白（05 §4.3 枚举处有硬换行）。前端超时窗口须覆盖最坏 5 调用路径（实测单格最坏 166.9 秒）。
3. **T16/T17（前端）**：`degrade_level>=1` 必渲染降级提示（实测 1/80 触发，非零）；批改结果 UI 不得承诺"两次批改完全一致"（存在 1 档级运行间波动）。
4. **T08（检索）**：2-gram 关键词必须 IDF 加权；L1 置信度不足时回退全库 L2。
5. **T23（测试收口）**：批改端到端用例的响应等待上限按最坏降级路径设定；关键词路由（`--router heuristic`）作为离线可复现基线保留在评估集。

## 7. 已知限制（不阻塞决策门，如实登记）

1. **单厂商单模型族**：T01 结论只在 MiMo 上成立（决策一已附重跑规程）；T02 模型路由只在 DeepSeek 单档位验证。
2. **语料代表性**：T01 语料全部为高分范文（档位分布窄，不支持推断真实考生分布）；T02 公开 PDF 的书签/目录页/文字层三特征高度耦合，与真实教材/讲义分布有偏差。
3. **人工评分相关性不可计算**：08 §3.1 的 Kendall tau 登记为"不适用"，补采带人工档位语料的建议已在 T01 §9-5 落字。
4. **T02 的 20 问可用率判定人为实现模型**，按 08 §8 分工需 QA（严过关）复签后才算正式签收。
5. **本机 Windows 既有测试噪声**：基线（`4a54991`）即存在的 31+ 处失败（POSIX 假设用例、缺可选依赖、旧包名 `coworker` 残留导入），与 V0.0 三个 spike 的纯增量改动无关，已由 T01/T03 的基线对照确认；建议单独立任务清理，避免污染后续 T05-T23 的回归门禁判读。
