## 3. 实现说明

严格按 06 §8-1：`ss/pdf_support.py` **零修改**，spike 自带 pypdf 逐页提取，与 `pdf_support.extract_text()` 的容错与 200k 上限同口径。

关键实现点（对应 06 条款）：

| 条款 | 实现 |
|---|---|
| §4.2-1 一页一片 | `page_no` = 物理页码（1 起），`chunk_seq` 页内序号（0 起） |
| §4.2-2 超长页二切 | 单页 >2000 字符按 `\n\s*\n` 段落边界聚合，单段超长则硬切，每片 ≤2000、重叠 0；单文档 3000 片上限 |
| §4.2-3 标题归属 | 每片取"最近一次匹配的标题行"（行首正则 + 长度 ≤40）；实现按"标题行偏移 ≤ 切片起始偏移"判定，页内偏移精确继承 |
| §5.1 L1 门控 | `section_title` 非空切片占比 ≥50% 才启用 L1 |
| §5.1 L2 | 关键词抽取（拉丁词元优先 + 中文 2-gram 去停用字）→ 命中词 IDF 加权 + 首次命中位置评分 → top_k |
| §5.1 章节跨度 | 按目录条目层级计算：一条目的跨度到下一个不深于自身的条目为止（书签层级语义混乱时跨度会收窄，见 §7-3） |
| §5.2 L1 未命中回退 | 路由选中章节但限域召回为空时，回退全库 L2，`used_retrieval` 如实标记 |
| §6.1 判空分支 | `no_text_layer`（全零 / 文字页为零 / 空页占比 >80%）、`pdf_broken`、`truncated_200k` 三态全覆盖 |
| §5.3 QA 组装 | `qa_context()` 12 000 字符预算、每片头部 `[p.X]` 标注、单片 2000 截断 |

## 7. 对 06 文档的差异与建议（T04 决策输入）

以下四条需要在 T04 决策门逐条落字。

### 7-1 标题行判据正则过窄（06 §4.2-3）

现文判据 `^\s*(第[一二三四五六七八九十\d]+[章讲部分节]|Chapter|章节编号\s+\S)` 不容忍"第 1 章"中的空格，也不支持"2.1 xxx"式编号标题。实测两种形态在真实中文 PDF 中都常见：

| 文档 | 标题形态 | spec 命中 |
|---|---|---|
| jc_hello_algo | `第 1 章 初识算法`（有空格） | 0 / 14 |
| jy_os_ch2 | `2.1 进程的基本概念`（编号式） | 0 / 7 |
| jc_docker、jy_xitike | `第三章 安装 Docker`、`第五章8题`（无空格） | 7/9、30/30 |

**建议**：放宽为容忍空白 `第\s*[一二三四五六七八九十百零\d]+\s*[章讲部分节篇]`，并追加编号式分支 `^\s*\d+(\.\d+)*\s+\S`。

### 7-2 只放宽正则会引入运行页眉污染（新发现，06 未覆盖）

放宽后 jc_hello_algo 抽出 270 个不同标题、jc_docker 280 个（≈1 条/页），原因是正文每页带运行页眉（如 `第 7 章 树 www.hello-algo.com 123`）。这会把 L1 目录路由的命中率从 90% 拖到 30%。

**建议**：教材类采用"**PDF 书签优先，文本行兜底**"的目录来源（本 spike 已实现为 `--toc-source outline`，即 08 §3.2 兜底口径，命中率达 90%）；若仍需文本行方案，必须叠加"同一标题 stem 出现在 ≥3 个不同页面则视为运行页眉"的过滤。

### 7-3 200k 字符截断对教材类影响显著（06 §6.1 口径的真实代价）

| 文档 | 总页数 | 已索引页 | 索引占比 |
|---|---|---|---|
| jc_hello_algo | 348 | 279 | 80.2% |
| jc_docker | 775 | 345 | 44.5% |

按 06 §6.1 的口径，一本 775 页教材只有前 44.5% 入库，后 55.5% 的内容在 B6 问答中永远不可达。**建议**：T05/T08 落地时为资料库场景单独设定上限（例如 1-2 MB 字符，或按"已含全部章节"提前判停），并与 `attachments.MAX_TEXT_CHARS` 的会话内附件口径解耦；否则需在产品层提示"仅解析前 N 页"。

### 7-4 附加结论

- 2-gram 关键词必须做 IDF 加权：交叉噪声词元（"入分""地没""有镜"）在未加权时会把相关切片挤出 top6（实测 jc_hello_algo S02 目标页排在第 9/13 位），加权后同类问题进入 top2。
- 纯检索型问题强制走 L1 会放大路由错误的代价（关键词型 top6 从 90% 降到 70%）。**建议**：L1 选中的章节限域召回为空时回退全库（已实现）；并考虑在 L1 置信度不足（选中章节与问题词重叠过弱）时也回退全库。
- 教材类"有书签无目录页 / 有目录页无书签"的混合形态普遍存在（jc_docker 有目录页但 `目录` 标题行检测为否），语料分档应以"结构可用性"为准，不能以文档名义判断。
- **PDF 书签里的"伪目录项"会击穿包含匹配**：jc_docker 附录术语表的 21 个单字母书签（A/B/C/…/V）能被任何含对应字母的行命中。真实模型路由测试（§4.4）正是被它整批打穿的。**建议**：T08 落地时对目录清单做最短标题门槛（建议规范化后 ≥4 字符），并过滤同一页面聚集的连续单字母项。
- **模型路由的章节命中率与确定性路由持平，但端到端召回明显更好**（全部问题 top6 0.8 → 0.95）：模型能选对语义相关但字面重叠弱的章节（如 S09/K04/K05/K07 的 Docker Hub）。06 §5.2 的章节 prompt 方案成立，T08 可直接沿用。
- **docker 书签的"章与节同层级"会让章节跨度塌缩**（第二章 的跨度按同深度下一项截成 1 页），S06 因此判未命中，尽管模型选章正确。**建议**：T08 计算跨度时若下一项与当前项同页或过近，应回退用"下一个更大层级条目"或"文档末页"兜底。
